# OES入替作業APP 仕様書 (SPEC.md)

GoogleカレンダーへOES入替作業の予定を登録するためのWebツールの仕様書。

## 0. 前提：複数人で使うアプリである

このアプリは**会社の複数の担当者が、それぞれ自分の端末で使うこと**を前提に設計する。
「一人用ツール」として単純化しないこと。特に作業当日の予定読み込みは、
**読み込む本人自身のGoogleカレンダーから読み込む**か、**該当の予定を手動でコピーして貼り付ける**、
のどちらかで各自が自分の作業を進める前提とする（詳細は 4.0 節）。

## 1. 概要

- 単一のHTMLファイル (`index.html`)。外部依存なし（プレーンなHTML/CSS/JavaScript、ロゴ・アイコンはdata URIで内包）。
- サーバーにFTPでアップロードして使用。必要に応じて `.htaccess` でBasic認証。
- **PWA（ホーム画面に追加してアプリのように使える）対応。** `<link rel="manifest">` にJSONをdata URIで直接埋め込む
  （別ファイルを増やさず1ファイル完結を保つ）。アイコンはマルチプリンター（SEIKO）の写真に「OES」バッジを重ねたもの。
- 画面は3タブ構成（カレンダー／作業当日／設定）。カレンダーは**質問形式（ウィザード）**で、
  ①業態・稼働件数・時間帯 → ②日付タップ → ③一覧確認・登録、の3ステップを1画面で完結する
  (旧版の「登録リスト」タブは「カレンダー」タブに統合)。パソコン・スマートフォン両対応、スマホでの利用を重視したコンパクトな余白。
- 配色は「青（メイン）× 空色（アクセント）」のバイカラー。
- カレンダーは常に当月の1か月だけを表示する（PC/スマホ共通。以前はPCで2か月並列だったが廃止）。
- 予定データはサーバーに保存しない。**設定のみ** ブラウザの `localStorage` に保存する。
- 操作マニュアルは `manual.html`（ヘッダー右上のリンクから別タブで開く）。

## 2. デザイン

- タイトル: 「OES入替作業APP」／ サブ: 「Googleカレンダー 一括登録ツール」
- 「カレンダー」画面の①カード（「どこの業態を、何件まわりますか？」）のタイトル横にマルチプリンター（SEIKO）、
  「作業当日」画面のタイトル横にマルチステーションの画像を、小さく（高さ34〜38px、`mix-blend-mode:multiply`）添える。
  data URIで内包。ファイル名は `device-printer.jpg` / `device-kitchen.jpg`。
- **配色は「青×空色」のバイカラー。** メインの青 `#1565C0`（`--blue`）とアクセントの空色 `#29B6F6`（`--sky`）の
  2色を軸にする。ヘッダー背景・選択中タブは青→空色のグラデーション、カード見出しの番号丸（`.step`）は空色、
  カード見出し帯・淡色ボタン・枠線などの薄色部分（`--blue-l` `--blue-l2` `--line` `--line-w`）は空色寄りの
  薄いトーンにする。背景 `#EAF7FD`。削除ボタンの赤・自動生成タグの緑・手動編集タグの琥珀色は意味付きの色として
  そのまま残す（バイカラーの対象外）。
- フォント: Hiragino Sans / Noto Sans JP / Meiryo 系。
- **全体にコンパクトな余白を採用する**（スマホでの利用が中心のため）。body・カード・見出しの padding は必要最小限にし、
  ボタン/入力欄の `min-height` は 34〜38px を目安にする（タップ領域34px以上は死守。それ未満に削らない）。
- レスポンシブ: 600px / 900px をブレークポイントとする（入力欄の文字サイズ・列数のみ変化。カレンダーは常に1か月）。
  - 900px以上: 登録リストのカードは3列、入力欄は13.5px。
  - 600px以上900px未満: カードは2列。
  - 600px未満: 1列。入力欄は16px（iOSの自動ズーム防止）、タップ領域は34px以上。
- 横スクロールは発生させない（幅の広い表は `overflow-x:auto` の中に入れる）。

### 2.1 PWA（ホーム画面への追加）

- `<link rel="manifest" href="data:application/manifest+json;base64,…">` でマニフェストを直接埋め込む（別ファイル不要）。
- マニフェストの内容: `name`/`short_name`「OES入替作業APP」、`display:"standalone"`、`theme_color:"#1565C0"`、
  `background_color:"#EBF3FB"`、`icons`（192/512、`purpose:"any"` と 512の `purpose:"maskable"`）。`start_url` は指定せず、
  ブラウザのフォールバック（マニフェストを参照した文書のURL）に任せる。
- アイコンは `assets/device-printer.jpg`（マルチプリンター写真）を土台に、中央下寄りに青いバッジで「OES」の文字を重ねたもの。
  マスカブル版は安全領域（中心80%）に収まるよう画像とバッジを一回り小さく配置する。
- `<link rel="apple-touch-icon">`（180x180）と `apple-mobile-web-app-*` 系メタタグでiOSのホーム画面追加にも対応。
- サービスワーカーは実装しない（オフライン動作は提供しない。近年のChromeはSW無しでもマニフェストのみでインストール可能）。
- アイコン生成手順は本仕様書の範囲外。再生成する場合は `assets/device-printer.jpg` を土台に、中央下へ角丸の青（`#1565C0`）
  バッジを描き、白のボールド文字で「OES」を重ねる（192/512/180/512-maskableの4サイズ）。

## 3. 画面1: カレンダー登録（質問形式のウィザードで1画面完結）

旧版は「カレンダーで選ぶ」→「登録リスト」の2タブに分かれ、次に複数日をまとめて選んでから
共通の内容を流し込む方式だった。**今版はさらに踏み込み、①業態・稼働件数・時間帯を選ぶ →
②カレンダーの日付をタップ → ③その場で開く確認ポップアップに店舗名・住所を件数分入力する、
という質問形式（ウィザード）にした。** 日付の複数選択やハイライト保持は行わず、タップ＝即アクション
という一発勝負のシンプルな操作にしている。

### 3.1 ①業態・稼働件数・時間帯を選ぶ

- `#w-gyotai`（業態）／`#w-count`（稼働件数、1〜30件から選ぶ）／`#w-staff`（担当者、任意）／
  `#w-ampm`（午前・午後のトグルボタン、**既定は午前**）の4項目。
- **稼働件数**は「この日にこの業態で何件まわるか」を表す。②で日付をタップしたときに開く確認
  ポップアップの入力欄の数（＝作られる登録件数）を決める。
- **午前・午後の切り替え**は、選んだ業態の時間帯（`slots`）のうち、午前なら1つめ（`slots[0]`）、
  午後なら2つめ（`slots[1]`）を使う。2つめの時間帯が設定されていない業態（例: 初期設定の
  オリーブの丘・華屋与兵衛）では、午後を選んでも1つめの時間帯にフォールバックする（ヒント文で
  その旨を案内する）。時刻・定型文は選んだ時間帯のものがそのまま使われ、②③では時刻の個別上書きも
  引き続きできる。
- 業態・件数・担当者・午前午後を変えても、既に登録リストに入っている件はさかのぼって変わらない
  （②のタップ時点の値がその回に作られる件に固定される）。

### 3.2 ②カレンダーで日付をタップ

- 当月を基準に表示。`‹` `›` で月移動、「今月へ」で当月に戻る。
- **PC・スマホともに常に1か月だけを表示する**（複数月の並列表示はしない）。パソコンで画面いっぱいに
  引き伸ばされて巨大化しないよう、`#cal-months` の最大幅を900px以上の画面で380pxに制限する。
- 日付をタップすると、**その場で3.3の確認ポップアップが開く**（複数選択・ハイライト保持はしない）。
  ①で業態が選ばれていない場合はトーストで案内してポップアップを開かない。
- 当日は青枠。登録リストに1件以上ある日は、選択状態の色ではなく「その日の登録件数」を表す
  バッジ（数字入りの丸、空色地）を表示する（`.day.has .cnt`）。同じ日に何度もタップして
  追加を重ねると、バッジの数字も増えていく。

### 3.3 確認ポップアップ（店舗名・住所を件数分入力）

- タップした日付・選んだ業態・午前/午後・時刻・件数・担当者を先頭にまとめて表示する。
- その下に、①で選んだ「稼働件数」ぶんの「店舗名・住所」入力欄が並ぶ（例: 3件なら3行）。
  住所は任意。件数が多い場合はポップアップ内でスクロールする（最大30件まで）。
- 「このN件を追加」を押すと、店舗名・住所のどちらかが入力されている行だけを登録リストに
  追加する（`confirmStoreModal()`）。両方空欄の行はスキップし、作成しない。
  1件も入力が無い状態で押すとトーストで案内する。
- 「キャンセル」または背景クリック・Escキーで何も作らず閉じる。
- 店舗名はここで語尾に「店」を自動補完してから登録する。住所はGoogleカレンダーの「場所」に入る。
- 追加された各件は、①で選んだ業態・時間帯（時刻・定型文）・担当者をそのまま引き継ぐ。

### 3.4 ③一覧で確認して登録（登録リスト）

- 1件＝1カード。**既定は折りたたみ表示**で、見出し行に「番号・要約（日付／時刻／業態／店舗名）・
  『登録』ボタン・開閉の矢印」だけを表示する（`toggleEntry(id)`で開閉）。稼働件数が多くても
  一覧が縦に伸びすぎないようにするための設計であり、全展開表示には戻さないこと。
- 見出しをタップして開くと、日付／業態／時間帯／開始／終了／担当者／店舗名／住所／説明文を
  個別に編集できる（複製・削除ボタンもここに現れる）。
- 業態を変えると、その業態の先頭の時間帯・時刻・定型文に切り替わる。担当者が未設定なら既定の担当者が入る。
- 説明文は既定で「定型文から自動生成」。手入力すると「手動で編集」に変わり自動更新を停止する。「定型文に戻す」で再生成。
- ツールバー: Googleカレンダーで順番に登録／ICSファイルで一括取込／空の行を追加／全て削除。
- 並び順は日付→開始時刻の昇順（`sortEntries()`。追加のたびに実行）。
- 件数はタブの「📅 カレンダー」バッジに表示する（`#list-count`。旧版の「📋 登録リスト」タブ廃止に伴い移設）。
- この一覧はあくまで「登録前の確認・個別編集・登録実行」のための補助画面であり、無くても①②の
  ポップアップ入力だけで登録データ自体は作れる（一覧を無くす／簡略化する場合は3.5の一括登録動線を
  どこか別の場所に必ず残すこと）。

### 3.5 Googleカレンダーへの一括登録（2通り、どちらもこの画面のツールバーから）
- **Googleカレンダーで順番に登録** — モーダルで「◯件目 / 全◯件」を表示し、「開く」を押すたびに
  1件ずつ新しいタブで開く（ポップアップブロック対策）。「とばす」で1件スキップ、「中止」で終了。ESCキーでも閉じる。
- **ICSファイルで一括取込** — `oes-YYYYMMDD.ics` をダウンロードし、GoogleカレンダーのUI
  （設定→インポート／エクスポート）で確認なしにまとめて取り込む。RFC5545準拠。`VTIMEZONE`
  （Asia/Tokyo, +0900固定）を含み、`DTSTART;TZID=Asia/Tokyo:` 形式。行は75オクテットで折り返す
  （マルチバイト文字を壊さないよう文字単位で判定）。BOM付きUTF-8。

## 4. 画面2: 作業当日

作業当日に、その日の作業内容を確認し、Google Chat へ貼り付ける連絡文をコピーするための画面。
**Google Chat への自動送信は行わない**（コピー → 手動で貼り付け → 送信）。入店・中間・退店の
連絡は、入力する手間をできるだけ減らし、コピー＆貼り付けだけで済むことを目的にしている
（②の定型文自動生成、③の機器台数入力、後述の「よく使う文」がいずれもこの目的のための機能）。

### 4.0 「自分（読み込む担当者）」の選択

- 作業当日タブの先頭に `#day-staff` セレクタ（「（指定なし）」＋担当者一覧）を置く。
- 選択値は `localStorage`（キー `oes-calendar-day-staff-v1`）に保存する。
  **これは端末固有の状態であり、`settings` オブジェクトの一部ではないため、設定の書き出し・読み込み（JSON）には含まれない。**
  同じ会社の設定ファイルを複数人が読み込んでも、各自の「自分」の選択はその端末にしか残らない。
- `getDayStaffId()` — 現在の選択値を返す。`renderDayStaffSelect()` — 担当者一覧から選択肢を作り直す（設定変更時・タブを開いたときに呼ぶ）。
- `resolveCalendarConn()` — 選択中の担当者に `calendarApiUrl` があればそれ（＋その担当者の `calendarQuery`）を返し、
  無ければ共通設定 `settings.calendarApiUrl`（フォールバック）を返す。戻り値は `{url, query, staff}`。

### 4.1 予定の読み込み（3通り）

| 方法 | 内容 | 事前準備 |
|---|---|---|
| 説明文の貼り付け | テキストエリアに貼り付けて解析。**標準の使い方**。選択中の担当者名を自動で `staff` に入れる | 不要 |
| 登録リストから探す | 同アプリの登録リストから当日分を抽出。**「自分」を選んでいれば `en.staffId` で絞り込む** | 不要 |
| Googleカレンダーから読み込む | `resolveCalendarConn()` が解決したURLを `GET` して当日分を取得。**選択中の担当者にURLがあればその方自身のカレンダー** | 担当者ごとのApps Script公開とURL登録（または共通URL） |

- 担当者を切り替えると、登録リスト由来の候補は自動で絞り込み直す（`onDayStaffChange()`）。カレンダー由来の候補は、次に読み込みボタンを押すまで保持する。
- 「登録リストから探す」で該当日に予定はあるが選択中の担当者のものが無い場合は、その旨をトーストで案内する（「指定なし」に戻せば全件表示されることを伝える）。

- 日付は上部の日付入力で切り替えられる（既定は当日）。
- 候補が複数ある場合は一覧から選択。1件のみなら自動選択。
- タブを開いたときは登録リストの候補を作り直すが、**表示中の連絡文は上書きしない**（カレンダー由来の候補も保持）。

### 4.2 説明文の振り分けロジック `splitReport()`

1. HTML混じりの説明文はプレーンテキストへ変換（`<br>`→改行、タグ除去、実体参照の復号）。
2. 空行（`\n\s*\n`）でブロックに分割し、空ブロックを除去。
3. 「中間報告の目印」を含む最初のブロックを `iMid`、その後ろで「退店連絡の目印」を含む最初のブロックを `iOut` とする。
   `iOut` が見つからない場合は `退店` でも探す。
4. 振り分け:
   - **入店連絡** = 先頭 〜 `iMid`（または `iOut`）の直前
   - **中間報告** = `iMid` のブロック
   - **退店連絡** = `iOut` 以降すべて（入店/退店時刻、機器カウントを含む）
5. どちらの目印も無い場合は全文を入店連絡に入れる。

目印は設定で変更可能（既定 `中間報告` / `退店報告`）。

### 4.3 業態・店舗名・時刻の推測 `detectFromText()`

- 登録済みの業態名を本文から検索し、見つかった行の業態名の直後のトークンを店舗名とみなす（数字始まりは除外）。
- `入店 HH:MM` / `退店 HH:MM` を正規表現で拾う。
- 登録リスト由来・カレンダー由来の場合は、そちらの値を優先する。

### 4.4 よく使う文（定型フレーズ）

- 連絡文カードの下に、控えめな帯（`.phrase-bar`）として小さなチップを並べる。押すとその文をコピーする。
- 予定を読み込んでいなくても使える（`dayCtx` に依存しない）。
- 差し込み文字に対応。`dayCtx` があれば `{業態}` `{店舗名}` `{日付}` `{開始}` `{終了}` `{担当者}` を置換する。
- チップの表示は1行目のみ・26文字で省略。コピーされるのは全文。
- 初期値: お疲れ様です／ご確認よろしくお願いします／現地に到着しました／作業を開始します／作業完了しました／ありがとうございました
- 設定画面「よく使う文（定型フレーズ）」で追加・修正・削除・並び替え（↑↓）ができる。0件にすると帯ごと非表示。

### 4.5 表示とコピー

- 「今日の作業」に 日付／業態 店舗名（22px）／時刻／住所（Googleマップリンク）／担当者 を表示。
- 連絡文は3つのテキストエリアで編集可能。各欄の見出しに「コピー」ボタンと「Chat」ボタンを並べて置く
  （押下後1.6秒だけ緑＋「コピーしました」）。
- コピーは `navigator.clipboard.writeText`（セキュアコンテキスト時）→ 失敗時は `textarea` + `execCommand('copy')` にフォールバック。
- 「定型文から作り直す」で読み込んだ内容から再分割。
- 「今日の作業」カードの「Google Chat を開く」、および①②③各欄の「Chat」ボタンは、いずれも
  `openStoreChat()` を呼ぶ（4.5-2参照）。

#### 4.5-1 機器の台数（③退店連絡のみ・入力した機器だけ反映）

- ③退店連絡のテキストエリア直上に、`MPR` `MST` `HT` `BC` `BP` 5種類の**プルダウン**（`<select>`、値は
  空欄または1〜10）を並べる（`#equip-row`）。単位はBPのみ「個」、他は「台」（`EQUIPMENT_UNITS`）。
  台数は多くても現場のプリンター・端末の台数を大きく超えないため、自由入力の数値欄ではなく
  1〜10のプルダウンにして誤入力（文字混入・桁間違い）を防ぐ。
- **説明文に含まれる機器台数の行（`MPR   台` のような空欄プレースホルダを含む）は、予定を読み込んだ時点で
  いったんすべて取り除く**（`stripEquipmentLines()`）。読み込み直後・何も選んでいない状態では、
  ③の本文に機器の行は一切表示されない。
- 数値を選んだ機器だけ、`コード + '   ' + 数値 + 単位` の形式で③の末尾にまとめて追記する
  （`rebuildEquipmentBlock()`）。追記順は選んだ順ではなく常に `MPR → MST → HT → BC → BP` の固定順。
  空欄に戻すとその行だけ消える。
- ③のテキストエリアを直接手で編集しても、プルダウンの値を変えるたびに機器の行だけを安全に置き換える
  （テキスト中の他の内容には触れない。ただし手動で `MPR` 等から始まる行を書いた場合はその行も対象になる）。
- 「登録リストから探す」等で別の作業を選び直す、または新しく貼り付け直すと、5つのプルダウンは空欄にリセットされる
  （`dayCounts` は `setDayCtx()` のたびに初期化）。「定型文から作り直す」では、選択済みの値は保持したまま
  本文だけ読み込み内容から作り直す。

#### 4.5-2 店舗ごとのGoogle Chatを直接開く

- **目的:** 作業のたびにGoogle Chatの一覧から該当の店舗のルーム／DMを探す手間をなくす。
- `settings.storeChats`（`[{id, tenpo, url}]`）に、店舗名とそのGoogle ChatのURLの対応を保持する
  （管理者が設定ファイルにまとめて配布することもできる。他のsettings項目と同様に書き出し・読み込みの対象）。
- `openStoreChat()` の動作:
  1. 表示中の作業（`dayCtx.tenpo`）の店舗名で `settings.storeChats` を検索する（`findStoreChat()`。
     店舗名の語尾「店」補完後の文字列で比較するため、「渋谷」でも「渋谷店」でも同じ登録に一致する）。
  2. 見つかればそのURLを新しいタブで開く（一覧を探す必要がない）。
  3. 見つからなければ、その場で `prompt()` を出してURLの入力を求める。入力されたURLは
     `settings.storeChats` に自動登録（`upsertStoreChat()`）してから開く。**次回以降は同じ店舗なら
     聞かずに直接開く。** 入力をキャンセルした場合は `https://chat.google.com/`（一覧画面）を開く。
  4. 作業を読み込んでいない場合（`dayCtx` が無い、店舗名が無い）は `https://chat.google.com/` を開く。
- 設定画面の「詳細設定」に一覧（`#store-chat-list`）を置き、店舗名・URLの追加・修正・削除ができる
  （3.3のポップアップ経由の自動登録と同じデータを編集する）。

### 4.6 Googleカレンダー連携（任意・担当者ごと）

- Google Apps Script のウェブアプリを窓口にする方式（OAuthクライアントの作成・審査は不要）。
- **URLは担当者ごとに持つのが基本。** 担当者が自分自身のGoogleアカウントでApps Scriptを公開すると、そのURLは
  「実行するユーザー: 自分」の設定により**その人自身のカレンダー**を返す。これを `settings.gyotai` と同様に
  共有される `settings.staff[].calendarApiUrl` / `calendarQuery` として保持する（＝管理者が全員分をまとめて配布できる）。
- `settings.calendarApiUrl` / `calendarQuery`（共通設定）は、担当者個別のURLが無い場合の**フォールバック**
  （会社共有のカレンダーを使う運用など）。個人のURLがあれば必ずそちらを優先する（`resolveCalendarConn()`）。
- リクエスト: `GET {URL}?date=YYYY-MM-DD[&q=絞り込み文字]`
- レスポンス: `{"date":"YYYY-MM-DD","events":[{"title","start","end","allDay","location","description"}]}`
- スクリプト本体は `apps-script/Code.gs`（全担当者共通・同じコードでよい）。**同じコードを `index.html` の `APPS_SCRIPT_CODE` が持っており、設定画面のモーダルから表示・コピーできる。片方を直したらもう片方も直すこと。**
- 公開設定は各自「実行するユーザー: 自分」「アクセスできるユーザー: 全員」。URLは実質的な秘密情報として扱う（他の担当者にも安易に教えない）。
- 未設定でも貼り付け方式で全機能が使える。

## 5. 画面3: 設定

設定タブは**シンプルさを優先**し、常時表示は4枚のカードのみとする。使用頻度の低い項目は
「詳細設定」1枚のアコーディオンにまとめ、既定は閉じておく。

| 表示 | カード |
|---|---|
| 常時表示 | 業態ごとの定型文・時間帯 |
| 常時表示 | 担当者と担当者定型文（担当者ごとに開閉するアコーディオン、先頭のみ既定で開く） |
| 常時表示 | よく使う文（定型フレーズ） |
| **折りたたみ**（既定は閉） | 詳細設定 ＝ 共通設定 ＋ 作業当日の連絡文の目印 ＋ 店舗ごとのGoogle Chat URL ＋ 共通のGoogleカレンダー連携（フォールバック） |
| 常時表示 | 設定の保存・持ち出し |

業態・担当者・詳細設定の開閉は、業態の時間帯アコーディオンと同じ仕組み（`.gy-item`/`.gy-head`/`.gy-body` と
`toggleGy(id)`）を再利用する。担当者の各行のDOM idは `gy-st-<担当者id>`、詳細設定は固定で `gy-advanced` とする。
（クラス名は業態向けに付けた名残りだが、担当者・詳細設定でも同じ見た目・挙動を再利用するために流用している。
このクラス名を業態専用と誤解して新しい折りたたみ要素を別実装で増やさないこと。）

### 5.1 業態ごとの定型文・時間帯
- 業態: 業態名 / タイトル書式（空欄なら共通設定）/ 既定の担当者 / 時間帯（1件以上）。
- 時間帯: 名称 / 開始 / 終了 / 定型文。
- 「＋ 業態を追加」「＋ 時間帯を追加」「削除」。業態も時間帯も最低1件は必要。

### 5.2 担当者と担当者定型文
- 担当者: 担当者名 / 連絡先・所属（任意）/ 担当者定型文 / ご本人のGoogleカレンダー連携URL（任意）/ 絞り込み文字（任意）。
- 各担当者は業態と同様に開閉できる（見出しは担当者名のみ。名前を編集すると見出しもその場で更新される）。
- 「＋ 担当者を追加」「この担当者を削除」。削除時は業態の既定担当者と登録リストの担当者から自動で外れる。
- 初期状態では担当者は0件。

### 5.3 よく使う文（定型フレーズ）

`settings.phrases`（`[{id, text}]`）を編集する。並び順がそのまま作業当日タブの並び順になる。

### 5.4 詳細設定（折りたたみ、既定は閉）

以下の3グループを1枚のカードにまとめる。フィールドのIDは変更前と同じ（`renderSettings()`/`onCommonChange()` は無改修）。

**共通設定**

## 11. 既知の制約

- 登録リストはリロード・タブを閉じると消える（未登録の予定があるときは離脱確認を表示）。
- `localStorage` が使えない環境（シークレットモード等）では設定が保存されない。動作自体は初期設定で継続する。
- 外部APIは、Googleカレンダー連携を設定した場合の Apps Script のURLのみ（未設定なら通信は一切発生しない）。
- Google Chat への自動送信は未実装（Incoming Webhookは Google Workspace 必須かつブラウザから直接POSTできないため、中継が必要になる）。「Chat」ボタンはあくまで該当店舗のChat画面を開くだけで、送信自体はコピー＆手動貼り付け。
- 店舗ごとのGoogle Chat URL（`settings.storeChats`）は店舗名の文字列一致（語尾「店」補完後）で検索するため、
  同じ店舗を表記ゆれ（例: 「渋谷駅前店」と「渋谷店」）で別々に入力すると別の店舗として扱われ、URLが引き継がれない。
- コピー機能は `https://` 配信が確実。非セキュアな環境では `execCommand` によるフォールバックで動作する。
- ICSインポートは確認なしで一括登録されるため、取込前の確認が必要。
