# OES入替作業APP 仕様書 (SPEC.md)

GoogleカレンダーへOES入替作業の予定を登録するためのWebツールの仕様書。

## 0. 前提：複数人で使うアプリである

このアプリは**会社の複数の担当者が、それぞれ自分の端末で使うこと**を前提に設計する。
「一人用ツール」として単純化しないこと。

- **設定は全員が同じ内容を使う。** 業態・時間帯・定型文・よく使う文などは、index.html と同じ場所に置く
  **`settings.json` 1ファイル**に保存し、全員がそこから読み込む（5.6節）。
- **設定を変更できるのは管理者だけ。** 設定タブは管理者パスワードでロックする（5.0節）。
- **アプリ内に「担当者」という概念は持たない。** 誰が使っても同じ画面・同じ設定で動く。
- **作業当日の予定は、各自が自分のGoogleカレンダーの説明文をコピーして貼り付ける**のが標準の使い方
  （4.1節）。Googleカレンダーからの直接読み込みは、利用者ごとにカレンダーが異なり共有設定と噛み合わないため停止した。

## 1. 概要

- 本体は1つのHTMLファイル (`index.html`)。外部ライブラリ・CDN・ビルドツールは使わない
  （プレーンなHTML/CSS/JavaScript、画面に使うロゴ・写真・スプラッシュのアイコンはdata URIで内包）。
- サーバーにFTPでアップロードして使用。必要に応じて `.htaccess` でBasic認証。
- **PWA（ホーム画面に追加してアプリのように使える）対応。** Androidで独立したアプリとして登録させるため、
  マニフェスト（`manifest.json`）とService Worker（`sw.js`）、アイコン（`icon-*.png`）は
  **`index.html` と同じ階層に実ファイルとして配置する**（2.1節）。アイコンはマルチプリンター（SEIKO）の写真に「OES」バッジを重ねたもの。
- **管理者パスワードは `index.html` に書かない。** サーバー上の設定ファイル（`config.php` または `config.json`）
  から読み込む（5.0節）。
- **起動時にスプラッシュを表示する。** OESアイコン＋アプリ名「OES入替作業APP」＋ウェルシス株式会社のバッジを
  1.2秒表示してフェードで消す。`pointer-events:none` で操作は妨げない。
- 画面は3タブ構成（カレンダー／作業当日／設定）。カレンダーは**質問形式（ウィザード）**で、
  ①業態と稼働件数 → ②日付と時間帯 → ③店舗名と住所 → ④一覧確認・Googleカレンダーへ登録、の4ステップを1画面で完結する
  (旧版の「登録リスト」タブは「カレンダー」タブに統合)。パソコン・スマートフォン両対応、スマホでの利用を重視したコンパクトな余白。
- 配色は「青（メイン）× 空色（アクセント）」のバイカラー（両色ともはっきり見えるトーンにする）。
- 月めくり式のカレンダーグリッドは廃止した。件数ぶんの行にそれぞれ日付入力（ネイティブの日付ピッカー）を
  持たせることで、1件目と2件目で違う日付を選べるようにしている。
- 予定データはサーバーに保存しない。**設定のみ** サーバー上の `settings.json`（1か所）に保存し、
  全員がそれを読み込んで使う。ブラウザの `localStorage` は、共有設定を読めなかったときの控え。
- 操作マニュアルは `manual.html`（ヘッダー右上のリンクから別タブで開く）。

## 2. デザイン

- タイトル: 「OES入替作業APP」／ サブ: 「Googleカレンダー 一括登録ツール」
- 「カレンダー」画面の①カード（「どこの業態を、何件まわりますか？」）のタイトル横にマルチプリンター（SEIKO）、
  「作業当日」画面のタイトル横にマルチステーションの画像を、小さく（高さ34〜38px、`mix-blend-mode:multiply`）添える。
  data URIで内包。ファイル名は `device-printer.jpg` / `device-kitchen.jpg`。
- **配色は「青×空色」のバイカラー。** メインの青 `#1565C0`（`--blue`）とアクセントの空色 `#29B6F6`（`--sky`）の
  2色を軸にする。ヘッダー背景・選択中タブは青→空色のグラデーション、カード見出しの番号丸（`.step`）は空色、
  カード見出し帯・淡色ボタン・枠線などの薄色部分（`--blue-l` `--blue-l2` `--line` `--line-w`）は空色寄りの
  薄いトーンにする。背景 `#EAF7FD`。削除ボタンの赤・自動生成タグの緑・手動編集タグの琥珀色は意味付きの色として
  そのまま残す（バイカラーの対象外）。
- フォント: Hiragino Sans / Noto Sans JP / Meiryo 系。
- **全体にコンパクトな余白を採用する**（スマホでの利用が中心のため）。body・カード・見出しの padding は必要最小限にし、
  ボタン/入力欄の `min-height` は 34〜38px を目安にする（タップ領域34px以上は死守。それ未満に削らない）。
- レスポンシブ: 600px / 900px をブレークポイントとする（入力欄の文字サイズ・列数のみ変化。カレンダーは常に1か月）。
  - 900px以上: 登録リストのカードは3列、入力欄は13.5px。
  - 600px以上900px未満: カードは2列。
  - 600px未満: 1列。入力欄は16px（iOSの自動ズーム防止）、タップ領域は34px以上。
- 横スクロールは発生させない（幅の広い表は `overflow-x:auto` の中に入れる）。

### 2.1 PWA（ホーム画面への追加）

- `<link rel="manifest" href="manifest.json">` で**実ファイル**を参照する。
  data URIのマニフェストではAndroidでWebAPKが生成されず、**Chromeのマークが重なったただのショートカット**に
  なってしまうため、data URIに戻さないこと。
- マニフェスト（`manifest.json`）の内容: `id:"./"`、`name`/`short_name`「OES入替作業APP」/「OES入替作業」、
  `start_url:"./index.html"`、`scope:"./"`、`display:"standalone"`、`theme_color:"#1565C0"`、
  `background_color:"#EAF7FD"`、`orientation:"portrait-primary"`、`lang:"ja"`、
  `icons`（`icon-192.png`・`icon-512.png` が `purpose:"any"`、`icon-512-maskable.png` が
  `purpose:"maskable"`）。**アイコンは実URLで書き、`index.html` と同じ階層に置く**
  （WebAPK生成時にサーバーから取得されるため。`assets/` の中だけに置くと、`assets/` を
  アップロードし忘れた環境でアイコンが取得できず、アイコンの無いショートカットになる）。
  マニフェストのファイル名は **`.webmanifest` ではなく `.json`** にする
  （未知の拡張子として扱うサーバーがあるため）。
- `sw.js`（Service Worker）を `navigator.serviceWorker.register('sw.js')` で登録する。`file://` では登録しない。
  方式はネットワーク優先（FTPで差し替えたら次に開いたときすぐ反映される）＋オフライン時のみキャッシュ。
  `settings.json` `config.json` `*.php` は共有設定が古くならないよう**キャッシュしない**。
- **Androidで独立したアプリ（WebAPK）として登録される条件**（1つでも欠けるとショートカット扱いになる）:
  ①`https://` 配信 ②実ファイルのマニフェスト ③`id`/`start_url`/`scope`/`display:standalone` ④192・512・
  maskableのアイコンが取得できる ⑤fetchハンドラを持つService Workerが登録されている。
  すでにショートカットとして追加済みの場合は、一度削除してから追加し直す必要がある。
- アイコンは `assets/device-printer.jpg`（マルチプリンター写真）を土台に、中央下寄りに青いバッジで「OES」の文字を重ねたもの。
  マスカブル版は安全領域（中心80%）に収まるよう画像とバッジを一回り小さく配置する。
- `<link rel="apple-touch-icon">`（180x180）と `apple-mobile-web-app-*` 系メタタグでiOSのホーム画面追加にも対応。
- サービスワーカーは実装しない（オフライン動作は提供しない。近年のChromeはSW無しでもマニフェストのみでインストール可能）。
- アイコン生成手順は本仕様書の範囲外。再生成する場合は `assets/device-printer.jpg` を土台に、中央下へ角丸の青（`#1565C0`）
  バッジを描き、白のボールド文字で「OES」を重ねる（192/512/180/512-maskableの4サイズ）。

## 3. 画面1: カレンダー登録（質問形式のウィザードで1画面完結）

旧版は「カレンダーで選ぶ」→「登録リスト」の2タブに分かれ、次に複数日をまとめて選んでから
共通の内容を流し込む方式だった。**今版は、①業態と稼働件数を選ぶ → ②件数ぶんの日付と時間帯を選ぶ →
③件数ぶんの店舗名と住所を入力する → ④一覧で確認してGoogleカレンダーへ登録、という
4ステップの質問形式（ウィザード）にした。** この順番は利用者が明示的に指定したものであり、
1つの入力欄にまとめ直さないこと。月をめくる形のカレンダーグリッドは廃止し、1件ごとにネイティブの
日付ピッカーを持たせることで、同じ日に複数件でも、1件目は10/1・2件目は10/10のように別の日でも、
自由に選べるようにしている。

**このアプリはまず「Googleカレンダーへ予定を登録するツール」として成立していることを最優先とする。**
作業当日タブ（4章）は、その上に載る補助機能という位置づけ。

### 3.1 ①業態と稼働件数を選ぶ

- `#w-gyotai`（業態）／`#w-count`（稼働件数、1〜30件から選ぶ）の2項目のみ。
  **担当者に関する項目は無い**（アプリ全体で担当者の概念を廃止済み）。
  業態プルダウンの並び順は設定画面での並び順（5.1節）に従う。
- 選んだ業態の午前・午後それぞれの時間帯の時刻を、参考情報として`#w-time-hint`に表示する
  （例:「午前 08:30〜09:30／午後 14:30〜15:30」）。2つめの時間帯が無い業態（初期設定のオリーブの丘・
  華屋与兵衛）は、午後も午前と同じ時刻になる旨を添える。
- **稼働件数**は「この業態で何件まわるか」を表し、②③に並ぶ入力行の数を決める。

### 3.2 ②日付と時間帯を選ぶ

- `#date-rows` に稼働件数ぶんの行（`.dt-row`、`data-idx`で0始まりの通し番号）が並ぶ。
- 各行は **日付**（`<input type="date">`）と **午前(AM)／午後(PM)のトグル**（既定は午前）を持つ。
  同じ日を複数件選んでも、別々の日を選んでもよい。
- 午前は業態の1つめの時間帯（`slots[0]`）、午後は2つめ（`slots[1]`、無ければ1つめ）を使う（`wizSlotFor()`）。
- 稼働件数を変えると行が過不足なく増減する。既に入力済みの行の内容は保持される。

### 3.3 ③店舗名と住所を入力

- `#store-rows` に②と**同じ件数**の行（`.st-row`）が並び、`data-idx`で②の行と1対1に対応する。
- 各行の見出し（`#st-when-<i>`）に、②で選んだ日付・時間帯を表示する（例:「1件目　10/1(木)　午前 08:30〜09:30」）。
  ②の日付・時間帯や①の業態を変えると、この見出しも即座に更新される（`updateRowWhen(i)` / `updateAllRowWhen()`）。
  日付が未選択の行は「日付を選んでください」と表示する。
- 各行は **店舗名** と **住所（任意）** を持つ。住所はGoogleカレンダーの「場所」に入る。
- 「このN件を登録リストへ」（`submitStoreRows()`）を押すと、②③を突き合わせて
  **②で日付が選ばれている行だけ**を登録リストに追加する。日付未選択の行は黙ってスキップし、
  スキップした件数があればトーストで知らせる。店舗名・住所は空欄のまま登録してもよい（あとから④で編集できる）。
  店舗名は登録時に語尾へ「店」を自動補完する。
- 登録が完了すると、②③の入力は空に戻る（行数＝稼働件数はそのまま維持する）。
- 1件も日付が選ばれていない状態で押した場合はトーストで案内し、何も登録しない。

### 3.4 ④一覧で確認してGoogleカレンダーへ登録（登録リスト）

- 1件＝1カード。**既定は折りたたみ表示**で、見出し行に「番号・要約（日付／時刻／業態／店舗名）・
  『登録』ボタン・開閉の矢印」だけを表示する（`toggleEntry(id)`で開閉）。稼働件数が多くても
  一覧が縦に伸びすぎないようにするための設計であり、全展開表示には戻さないこと。
- 見出しをタップして開くと、日付／業態／時間帯／開始／終了／店舗名／住所／説明文を個別に編集できる
  （複製・削除ボタンもここに現れる）。
- 業態を変えると、その業態の先頭の時間帯・時刻・定型文に切り替わる。
- 説明文は既定で「定型文から自動生成」。手入力すると「手動で編集」に変わり自動更新を停止する。「定型文に戻す」で再生成。
- ツールバー: Googleカレンダーで順番に登録／ICSファイルで一括取込／空の行を追加／全て削除。
- 並び順は日付→開始時刻の昇順（`sortEntries()`。追加のたびに実行）。
- 件数はタブの「📅 カレンダー」バッジに表示する（`#list-count`。旧版の「📋 登録リスト」タブ廃止に伴い移設）。

### 3.5 Googleカレンダーへの一括登録（2通り、どちらもこの画面のツールバーから）
- **Googleカレンダーで順番に登録** — モーダルで「◯件目 / 全◯件」を表示し、「開く」を押すたびに
  1件ずつ新しいタブで開く（ポップアップブロック対策）。「とばす」で1件スキップ、「中止」で終了。ESCキーでも閉じる。
- **ICSファイルで一括取込** — `oes-YYYYMMDD.ics` をダウンロードし、GoogleカレンダーのUI
  （設定→インポート／エクスポート）で確認なしにまとめて取り込む。RFC5545準拠。`VTIMEZONE`
  （Asia/Tokyo, +0900固定）を含み、`DTSTART;TZID=Asia/Tokyo:` 形式。行は75オクテットで折り返す
  （マルチバイト文字を壊さないよう文字単位で判定）。BOM付きUTF-8。

## 4. 画面2: 作業当日

作業当日に、その日の作業内容を確認し、Google Chat へ貼り付ける連絡文をコピーするための画面。
**Google Chat への自動送信は行わない**（コピー → 手動で貼り付け → 送信）。入店・中間・退店の
連絡は、入力する手間をできるだけ減らし、コピー＆貼り付けだけで済むことを目的にしている
（②の定型文自動生成、③の機器台数入力、後述の「よく使う文」がいずれもこの目的のための機能）。

### 4.1 予定の読み込み

**「業態を選んで店舗名を入れるだけ」で連絡文が作れることが、この画面の主役である**（4.1.1）。
Googleカレンダーの説明文の貼り付け（`#day-paste` → `loadDayFromPaste()`）と、
「このアプリの登録リストから探す」（`loadDayFromList()`）は、同じカード内の折りたたみ（`#gy-paste`）に
まとめた**補助動線**とする。定型文とは違う内容で連絡したいときに使う。
主動線が埋もれるような画面変更をしないこと。

**Googleカレンダーからの直接読み込みは廃止した。** 利用者ごとにカレンダーが異なり、
全員で1つの設定を共有するこのアプリの方針と噛み合わないため。設定項目だけは5.4節に残してある。

- 日付は上部の日付入力で切り替えられる（既定は当日）。
- 候補が複数ある場合は一覧から選択。1件のみなら自動選択。
- タブを開いたときは登録リストの候補を作り直すが、**表示中の連絡文は上書きしない**（カレンダー由来の候補も保持）。

### 4.1.1 業態と店舗名から連絡文を作る（主動線）

- 「🛠️ 作業当日」タブの先頭で、**業態（`#day-gyotai`）と店舗名（`#day-tenpo`）だけ**を指定して
  「この内容で連絡文を作る」（`buildDayFromGyotai()`）を押すと、その業態・時間帯の定型文から
  ①入店連絡／②中間報告／③退店連絡を生成する。Googleカレンダーを開く必要はない。
- 時間帯（`#day-slot-field`）は、その業態の時間帯が**2つ以上あるときだけ**表示する（`renderDaySlotRow()`）。
  1つしかない業態では選ばせない。
- 店舗名は `applySuffix()` で語尾（既定は「店」）を補ってから使う。生成した内容は `setDayCtx()` に渡すため、
  「今日の作業」の表示・Chatボタンの業態＋店舗照合・よく使う文の差し込み文字も従来どおり働く。
- ③退店連絡の機器台数（MPR/MST/HT/BC/BP、1〜10のプルダウン）は従来どおりで、選んだ機器だけが追記される。
- Googleカレンダーの説明文の貼り付けは、同じカード内の折りたたみ（`#gy-paste`）に置いた**補助動線**とする。

### 4.2 説明文の振り分けロジック `splitReport()`

1. HTML混じりの説明文はプレーンテキストへ変換（`<br>`→改行、タグ除去、実体参照の復号）。
2. 空行（`\n\s*\n`）でブロックに分割し、空ブロックを除去。
3. 「中間報告の目印」を含む最初のブロックを `iMid`、その後ろで「退店連絡の目印」を含む最初のブロックを `iOut` とする。
   `iOut` が見つからない場合は `退店` でも探す。
4. 振り分け:
   - **入店連絡** = 先頭 〜 `iMid`（または `iOut`）の直前
   - **中間報告** = `iMid` のブロック
   - **退店連絡** = `iOut` 以降すべて（入店/退店時刻、機器カウントを含む）
5. どちらの目印も無い場合は全文を入店連絡に入れる。

目印は設定で変更可能（既定 `中間報告` / `退店報告`）。

### 4.3 業態・店舗名・時刻の推測 `detectFromText()`

- 登録済みの業態名を本文から検索し、見つかった行の業態名の直後のトークンを店舗名とみなす（数字始まりは除外）。
- `入店 HH:MM` / `退店 HH:MM` を正規表現で拾う。
- 登録リスト由来・カレンダー由来の場合は、そちらの値を優先する。

### 4.4 よく使う文（定型フレーズ）

- 連絡文カードの下に、控えめな帯（`.phrase-bar`）として小さなチップを並べる。押すとその文をコピーする。
- 予定を読み込んでいなくても使える（`dayCtx` に依存しない）。
- 差し込み文字に対応。`dayCtx` があれば `{業態}` `{店舗名}` `{日付}` `{開始}` `{終了}` を置換する。
- チップの表示は1行目のみ・26文字で省略。コピーされるのは全文。
- 初期値: お疲れ様です／ご確認よろしくお願いします／現地に到着しました／作業を開始します／作業完了しました／ありがとうございました
- 設定画面「よく使う文（定型フレーズ）」で追加・修正・削除・並び替え（↑↓）ができる。0件にすると帯ごと非表示。
- 設定画面の編集欄は**1行の `<input>`** とし、↑↓・削除ボタンと横並びにする（`.ph-row`）。
  縦に長くならないようにするための指定なので、複数行の `<textarea>` に戻さないこと。

### 4.4.1 入力内容の一時保存（下書き）

- スマートフォンでは画面の更新やアプリの切り替えだけで入力が消えるため、**入力途中の内容**を
  `localStorage`（キー `oes-calendar-draft-v1`）に400msの遅延つきで保存する（`saveDraftSoon()`）。
- 保存対象: 作業当日タブ（業態・店舗名・日付・時間帯・生成した連絡文・機器台数・貼り付け欄）と、
  カレンダータブ①②③の入力（業態・稼働件数・各行の日付/午前午後/店舗名/住所）。
- **登録リスト（`entries`）は従来どおり保存しない。** 共有設定でもなく、その端末だけの一時的な控えである。
- 復元（`restoreDraft()`）は**共有設定の読み込みが完了してから**行う。先に戻すと、
  設定に合わせて行を作り直したときに消えてしまうため。復元したときはトーストで知らせる。
- 保存から**24時間**経った下書きは使わずに削除する（前日の入力が残らないように）。

### 4.5 表示とコピー

- 「今日の作業」に 日付／業態 店舗名（22px）／時刻／住所（Googleマップリンク）を表示。
- 連絡文は3つのテキストエリアで編集可能。各欄の見出しに「コピー」ボタンと「Chat」ボタンを並べて置く
  （押下後1.6秒だけ緑＋「コピーしました」）。
- コピーは `navigator.clipboard.writeText`（セキュアコンテキスト時）→ 失敗時は `textarea` + `execCommand('copy')` にフォールバック。
- 「定型文から作り直す」で読み込んだ内容から再分割。
- 「今日の作業」カードの「Google Chat を開く」、および①②③各欄の「Chat」ボタンは、いずれも
  `openStoreChat()` を呼ぶ（4.5-2参照）。

#### 4.5-1 機器の台数（③退店連絡のみ・入力した機器だけ反映）

- ③退店連絡のテキストエリア直上に、`MPR` `MST` `HT` `BC` `BP` 5種類の**プルダウン**（`<select>`、値は
  空欄または1〜10）を並べる（`#equip-row`）。単位はBPのみ「個」、他は「台」（`EQUIPMENT_UNITS`）。
  台数は多くても現場のプリンター・端末の台数を大きく超えないため、自由入力の数値欄ではなく
  1〜10のプルダウンにして誤入力（文字混入・桁間違い）を防ぐ。
- **説明文に含まれる機器台数の行（`MPR   台` のような空欄プレースホルダを含む）は、予定を読み込んだ時点で
  いったんすべて取り除く**（`stripEquipmentLines()`）。読み込み直後・何も選んでいない状態では、
  ③の本文に機器の行は一切表示されない。
- 数値を選んだ機器だけ、`コード + '   ' + 数値 + 単位` の形式で③の末尾にまとめて追記する
  （`rebuildEquipmentBlock()`）。追記順は選んだ順ではなく常に `MPR → MST → HT → BC → BP` の固定順。
  空欄に戻すとその行だけ消える。
- ③のテキストエリアを直接手で編集しても、プルダウンの値を変えるたびに機器の行だけを安全に置き換える
  （テキスト中の他の内容には触れない。ただし手動で `MPR` 等から始まる行を書いた場合はその行も対象になる）。
- 「登録リストから探す」等で別の作業を選び直す、または新しく貼り付け直すと、5つのプルダウンは空欄にリセットされる
  （`dayCounts` は `setDayCtx()` のたびに初期化）。「定型文から作り直す」では、選択済みの値は保持したまま
  本文だけ読み込み内容から作り直す。

#### 4.5-2 業態・店舗ごとのGoogle Chatを直接開く

- **目的:** 作業のたびにGoogle Chatの一覧から該当の業態・店舗のルーム／DMを探す手間をなくす。
- `settings.storeChats`（`[{id, gyotai, tenpo, url}]`）に、**業態＋店舗名の組み合わせ**とその
  Google ChatのURLの対応を保持する（同じ店舗名でも業態が違えばルームが異なる場合があるため、
  店舗名だけでなく業態も含めて照合する）。管理者が設定ファイルにまとめて配布することもできる
  （他のsettings項目と同様に書き出し・読み込みの対象）。
- `openStoreChat()` の動作:
  1. 表示中の作業（`dayCtx.gyotai` / `dayCtx.tenpo`）の業態＋店舗名で `settings.storeChats` を検索する
     （`findStoreChat(gyotai, tenpo)`。店舗名は語尾「店」補完後の文字列で比較するため、「渋谷」でも
     「渋谷店」でも同じ登録に一致する。業態名は完全一致）。
  2. 見つかればそのURLを開く（一覧を探す必要がない）。
  3. **見つからない場合は、案内や入力ダイアログを出さず、そのまま一般のGoogle Chat
     （`https://chat.google.com/`）を開く。** 以前あった「未登録なら`prompt()`でURLを聞いて自動登録する」
     動作は廃止した（作業の合間にダイアログで足止めされるのを避けるため）。
  4. 作業を読み込んでいない場合（`dayCtx` が無い、店舗名が無い）も同様に一般のGoogle Chatを開く。
- **タブは1枚だけ使い回す。** `window.open(url, 'oes-store-chat')` と名前付きで開き、
  **直前と同じ業態＋店舗であればURLを読み込み直さず、そのタブを前面に出すだけ**にする
  （`chatWin` / `chatWinKey`）。未登録で一般のChatを開いた場合でも、そこで開いた部屋がそのまま残るため、
  ①②③の各ボタンを続けて押しても一覧に戻らない。ウィンドウ参照が失われている場合は開き直す。
  ※ Google Chat には「店舗名で検索した状態」を開く公開URLが無いため、部屋を直接開くには
  そのルームのURLを登録しておく必要がある。
- 事前登録・修正・削除は、設定画面の「詳細設定」内の一覧（`#store-chat-list`）から行える
  （業態・店舗名・URLの3項目を編集できる、`addStoreChat()` / `setStoreChatField()` / `removeStoreChat()`）。
- **作業当日タブの「Chatを登録」からもその場で登録できる**（`openChatRegister()` / `saveChatRegister()`）。
  表示中の業態＋店舗名に対してURLを貼り付けるだけでよく、既存の登録があれば上書きする。
  設定がロックされている場合は、モーダル内の管理者パスワード欄で解除してから保存する
  （現場でその場で登録できるようにするための導線。ボタンを押したときだけ開き、`prompt()` は使わない）。

### 5.0 管理者ロック

- **設定の変更は管理者だけが行う。** 設定タブは既定でロックされ、`#pane-set` に `locked` クラスが付く。
  ロック中はCSSで、設定カード内の入力・選択・ボタンを操作不可（`pointer-events:none` ＋ 半透明）にする。
- **パスワードの平文は `index.html` に書かない。** `verifyAdminPassword(v, cb)` が次の順で照合する。
  1. **`admin-auth.php`**（あれば）へ `{password}` をPOSTし、`{"ok":true|false}` の返答に従う。
     パスワードは `config.php` の中だけにあり、ブラウザへは一切送られない（**推奨・最も安全**）。
  2. 無ければ **`config.json`** の `adminPasswordHash`（SHA-256。ソルトは `ADMIN_SALT` = `'oes-calendar:'`、
     つまり `sha256('oes-calendar:' + パスワード)` の16進64桁）と照合する。起動時に `loadAdminConfig()` が読み込む。
  3. `config.json` も無ければ、組み込みの `ADMIN_HASH_FALLBACK`（初期パスワードのハッシュ）と照合する。
  1が404等で失敗した場合は `adminConfig.useEndpoint = false` にして以降は試さない。
  `file://` で開いた場合は1・2を行わず3のみ。
- SHA-256は外部ライブラリを使わず `sha256Hex()` で実装する（`crypto.subtle` は `https://` でないと使えないため）。
- 照合が通ると `sessionStorage`（キー `oes-calendar-admin-unlocked`）に解除状態を持つ（ブラウザを閉じると再びロック）。
  「ロックする」（`lockSettings()`）でいつでも戻せる。
- 入力された平文は `adminPw`（**メモリ上のみ**。`lockSettings()` で破棄）に保持し、`settings-save.php` への
  保存POSTにだけ使う。`localStorage` / `sessionStorage` には保存しない。リロード等で失われていた場合は
  `currentAdminPw()` が保存時に一度だけ聞き直す。
- **ロック中でもできること**: 設定内容の閲覧、折りたたみの開閉、「共有設定を再読み込み」（`#lock-card`内）、
  「アプリとしてインストール」（`#install-card`）。これらは管理者以外にも必要なため、ロック対象から除外する。
- 変更系の関数（`addGyotai()` `moveGyotai()` `removeGyotai()` `addPhrase()` `movePhrase()` `removePhrase()`
  `addStoreChat()` `removeStoreChat()` `importSettings()` `resetSettings()` `saveSharedSettings()`）には
  `requireAdmin()` を入れ、CSSをすり抜けた場合にも変更されないようにする。
- **`admin-auth.php` を使わない場合、`index.html` や `config.json` から読めるのはハッシュだけで平文は分からないが、
  総当たりまでは防げない**（画面の誤操作防止が主目的）。厳密に制限したい場合は `admin-auth.php` を置くか、
  `deploy/.htaccess.sample` のBasic認証を併用する。
- パスワードの変更: PHPが使える場合は `config.php` の `admin_password` を書き換えるだけ。使えない場合は
  `deploy/make-hash.html` を**手元のブラウザで**開いて新しいハッシュを作り、`config.json` を差し替える
  （`make-hash.html` はサーバーに置かない）。

### 5.1 業態ごとの定型文・時間帯

### 5.5 共有設定の保存（全員で同じ内容を使う）

- **保存場所は index.html と同じ場所の `settings.json` 1つだけ。** 全員がここから読み込む。
- 起動時に `loadSharedSettings()` が `fetch('settings.json?t=…')` で取得し、`normalizeSettings()` を通して適用、
  同時に `localStorage`（キー `oes-calendar-settings-v1`）へ控えを残す。取得できない場合は
  控え → 初期設定の順にフォールバックし、状態を `#shared-status` に表示する。
  `file://` で直接開いた場合はブラウザの制限で取得できないため、試行せず案内だけ出す。
- 「共有設定を再読み込み」（`reloadSharedSettings()`）でいつでも取り直せる（ロック中でも可）。
- 「共有設定を保存」（`saveSharedSettings()`、管理者のみ）の動作:
  1. `settings-save.php`（任意設置）へ `{password, settings}` をPOSTし、成功すればサーバー上の
     `settings.json` が更新される（＝その場で全員に反映）。
  2. エンドポイントが無い・失敗した場合は `settings.json` をダウンロードする。
     **index.html と同じ場所へFTPでアップロードすれば同じ結果になる。**
- 「ファイルから読み込む」（`importSettings()`）と「初期設定に戻す」（`resetSettings()`）も管理者のみ。
  読み込み時は `normalizeSettings()` で検証・補完し、壊れたファイルは読み込まない。
- `deploy/settings-save.php` はPHPが動くサーバー向けのサンプル。パスワードは `config.php` から読み込んで照合し、
  一時ファイル経由で `settings.json` を書き換える。PHPが使えない場合は置かなくてよい（上記2の手順で運用する）。

### 5.5.1 未共有の変更の検知と自動保存

- 管理者が設定を変更すると `markSharedDirty()` が `sharedState.dirty` を立て、設定タブの先頭に
  未共有バナー（`#dirty-bar`）を表示する。「今すぐ全員へ共有する」ボタンから保存できる。
  未共有のままページを離れようとした場合は離脱確認を出す。
- 起動時に `probeSaveEndpoint()` が `settings-save.php` へ空のJSONをPOSTし、応答から可否を判定する。
  「パスワードが違います」等のJSONが返れば利用可、`<?php` がそのまま返ればPHP未実行、
  `config.php がありません` なら設定ファイル欠落、404なら未設置、と区別する。
- 利用可と判定された場合のみ、設定変更の1.5秒後に**自動でサーバーへ保存する**（押し忘れ防止）。
  利用不可の場合は自動保存せず、バナーで「保存してFTPアップロードが必要」と案内する。
- 保存に成功すると `dirty` を解除し、ダウンロードにフォールバックした場合は
  「アップロードが済むまで未共有」として `dirty` を維持する。

### 5.5.2 サーバーの状態をチェック（診断）

- 設定タブの `#diag-card` →「チェックする」（`runDiagnostics()`）で、次を順に確認して
  ✅ ⚠️ ❌ と対処方法を日本語で表示する。**ロック中でも実行できる**（管理者以外の端末から
  原因を確認する用途があるため、`#lock-card` `#install-card` と同様にロック対象から除外する）。
  1. `https://` で開いているか（`file://` の場合はその時点で終了）
  2. `settings.json` が取得できるか。取得できた場合は**業態の並び順**とサーバー上の更新日時を表示する
     （PCとスマホで見比べれば、保存し忘れかどうかがすぐ分かる）
  3. `settings-save.php` が使えるか（使えない理由も表示）
  4. 管理者パスワードの設定ファイル（`admin-auth.php` / `config.json`）の有無
  5. `manifest.json` の取得と、そこに書かれたアイコンが全て取得できるか
  6. `sw.js` の取得と Service Worker の登録状態
  7. インストール状態（スタンドアロン起動中か／`beforeinstallprompt` を受け取っているか）
- `loadSharedSettings()` の成功時は `#shared-status` にも業態の並び順と更新日時を出す。

### 5.5.3 アプリインストールへの導線

- 画面最下部（コピーライトのすぐ上）に「📱 アプリインストールはこちらから」（`.install-link` →
  `openInstallHelp()`）を常時置く。どのタブからでも到達できる。
- `beforeinstallprompt` を受け取っていればそのままインストールダイアログを出す。
  すでにスタンドアロン起動中なら「すでにアプリとして起動しています」と知らせる。
- どちらでもない場合は、UAから iPhone / Android / パソコン を判定して、その端末の手順をモーダルで案内し、
  「設定を開いてチェックする」から診断（5.5.2）へ誘導する。

### 5.6 アプリとしてインストール

- ブラウザの`beforeinstallprompt`イベントを受け取れた場合だけ、「📱 アプリとしてインストール」ボタン
  （`#btn-install-pwa`）を表示する（既定は`hidden`）。イベントは`preventDefault()`した上で`deferredInstallPrompt`
  に保持しておき、ボタン押下時（`installPwa()`）に`deferredInstallPrompt.prompt()`を呼んでインストール
  ダイアログを出す。選択が終わったら（`userChoice`解決後）ボタンを再び隠す。
- `appinstalled`イベントでも同様にボタンを隠し、トーストで案内する。
- このイベントに対応しないブラウザ（iOS Safariなど）ではボタンは常に非表示のままとし、代わりに
  「ブラウザのメニューから『アプリをインストール』または『ホーム画面に追加』をお試しください」という
  案内文と、手動手順を載せた`manual.html#s2b`へのリンクを常に表示する。

## 10. 認証・配置

- 配置: ドキュメントルート配下に `index.html` / `manual.html` / `assets/` を同じ階層で置く。
  共有設定を使う場合は同じ場所に `settings.json`（アプリが書き出したもの）を置く。
  PHPが動くサーバーなら `deploy/settings-save.php` を `settings-save.php` として同じ場所に置くと、
  アプリの「共有設定を保存」からサーバーへ直接保存できる（`settings.json` を書き込むためフォルダに書き込み権限が必要）。
- Basic認証を使う場合は `deploy/.htaccess.sample` を参照（`AuthUserFile` は配置先の絶対パスに書き換える）。
- 認証情報はリポジトリに含めない。

## 11. 既知の制約

- 登録リストはリロード・タブを閉じると消える（未登録の予定があるときは離脱確認を表示）。
- 共有設定（`settings.json`）は静的ファイルとして誰でも読める。秘密にしたい情報（Chatの内部URLなど）を
  入れる場合は、`deploy/.htaccess.sample` のBasic認証などでフォルダ全体を保護すること。
- 管理者パスワードは `admin-auth.php` を置かない限り、ハッシュがブラウザから読める状態になる
  （平文は分からないが総当たりは防げない）。設定画面の誤操作防止が主目的であり、厳密なアクセス制御ではない。
- PWAは `https://` 配信でないとAndroidで独立したアプリ（WebAPK）にならず、アイコンにChromeのマークが付いた
  ショートカットになる。また `manifest.json` `sw.js` `icon-*.png` を置き忘れた場合も同様。
- `settings.json` の読み込みは `file://` では動かない（ブラウザの制限）。サーバーに置いて使うこと。
- `localStorage` が使えない環境（シークレットモード等）では設定が保存されない。動作自体は初期設定で継続する。
- 外部APIは、Googleカレンダー連携を設定した場合の Apps Script のURLのみ（未設定なら通信は一切発生しない）。
- Google Chat への自動送信は未実装（Incoming Webhookは Google Workspace 必須かつブラウザから直接POSTできないため、中継が必要になる）。「Chat」ボタンはあくまで該当店舗のChat画面を開くだけで、送信自体はコピー＆手動貼り付け。
- 業態・店舗ごとのGoogle Chat URL（`settings.storeChats`）は業態名の完全一致＋店舗名の文字列一致
  （語尾「店」補完後）で検索するため、同じ店舗を表記ゆれ（例:「渋谷駅前店」と「渋谷店」）や
  業態名の表記違いで別々に入力すると別の店舗として扱われ、URLが引き継がれない。未登録の場合は
  案内なしで一般のGoogle Chatが開くだけなので、事前に「詳細設定」から登録しておく必要がある。
- PWAの自動インストールボタンは`beforeinstallprompt`イベントに対応したブラウザ（Android Chrome/Edge等）
  でのみ表示される。iOS Safari等では表示されず、手動手順（メニューからのインストール）の案内のみになる。
- コピー機能は `https://` 配信が確実。非セキュアな環境では `execCommand` によるフォールバックで動作する。
- ICSインポートは確認なしで一括登録されるため、取込前の確認が必要。
