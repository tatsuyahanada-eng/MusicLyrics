# parking-finder

Google カレンダーの予定を起点に、目的地近くの**コインパーキング（時間貸し）**の候補を探して予定に追記するスキル。
用途は「訪問・打ち合わせなどで、その場所に一時的に行き、近くに短時間だけ車を停めたい」ケース。
月極・駐輪場（自転車）・車庫などは目的に合わないので既定で除外する。

**検索は `WebSearch` による簡易版。** 以前は Google Maps API（Geocoding / Places / Distance Matrix）を使っていたが、
API キー発行に Google Cloud の請求（Billing）設定が必要になり、ユーザーの費用負担なしでは運用できなくなったため廃止した。
そのため**正確な距離・所要時間は算出できない**。「その地域でよく使われているコインパーキングの候補」という
ざっくりした目安情報にとどまる前提で使うこと。

## このスキルが行うこと（全体像）

```
① 指定された日付の予定をカレンダーから取得
     ↓
② 「場所（location）」欄に住所が入っている予定だけを対象にする（住所なしはスキップ）
     ↓
③ 基準住所の近くのコインパーキング候補を WebSearch で調べる（名前・分かれば運営会社）※複数可
     ↓
④ （可能なら）駐車場の料金の目安を補足
     ↓
⑤ 結果を、その予定の説明欄（description）に追記する
     ↓
⑥ その日の 18:00〜19:00 に「JCOM交通費精算」予定を作成し、
   処理した各予定の住所だけを説明文に列挙する（既にあれば更新）
```

## 前提（動かす前に必要なもの）

- **Google カレンダー コネクタ**（予定の読み取り＋**書き込み**の両方）。これだけでよく、外部 API キーは不要。

前提が整っていない兆候が出たら、途中で止めてユーザーに伝えること。

- カレンダー系の MCP ツールが見つからない → コネクタ未接続。claude.ai の 設定 → コネクタ で Google カレンダーを接続し、**予定の更新まで許可**されているか確認するよう案内する。

## 手順

### 0. 前提の確認

- カレンダーのツールは名前がコネクタによって変わる。`ToolSearch` で `google calendar events` のように検索し、`list_calendars` / `list_events` / `get_event` / `update_event` / `create_event` に相当するツールを特定する。見つからなければコネクタ未接続としてユーザーに伝える。

### 1. 対象の予定を取得する

- ユーザーが指定した日付（「明日」「7月25日」など）を具体的な日付に解決する。曖昧なら確認する。時刻は指定タイムゾーン（日本なら `Asia/Tokyo`）で解釈する。
- **既定の対象カレンダーは「その他業務(法人含)」**（`o139e347hvc5v9c5a043bh5v18@group.calendar.google.com`）。ユーザーが別のカレンダーを指定した場合はそちらを使う。ID が変わっている可能性もあるので、`list_calendars` で「その他業務」を含む名前のカレンダーを解決してから使うと確実。
- 予定は複数のカレンダーに分かれていることがある。ユーザーが「全部のカレンダー」等と指定した場合は、`list_calendars` の各カレンダーを順に `list_events` で確認する。どのカレンダーか曖昧なら確認する。
- その日の予定を `list_events`（`startTime`/`endTime` にその日の 00:00〜23:59、`orderBy: startTime`）で取得する。

### 2. 対象を「住所が入っている予定」に絞る

- **「場所（location）」欄に住所が入っている予定だけを対象にする。** 場所欄が空の予定は基準地点が無いのでスキップし、スキップした予定名をユーザーに一言伝える（駐車場検索の対象外である旨）。

### 3〜4. コインパーキング候補を WebSearch で調べる

対象の各予定について `WebSearch` ツールを使う。ピンポイントの番地・建物名まで含めて検索すると、駅前の有名駐車場など無関係な結果しか出てこないことが多いので、**番地・建物名を落として市区町村＋町名（丁目）レベルまでに削った住所**で検索する。

```
<都道府県><市区町村><町名・丁目> コインパーキング
```

- 0 件・関係の薄い結果しか出ない場合は、町名をさらに削って市区町村レベルにする、または「タイムズ」「三井のリパーク」「パラカ」などチェーン名を足して再検索する。
- 一時利用に向かない月極・駐輪場（自転車）・車庫・トレーラー等の名称は候補から除外する。
- **重要な制約**: この方法では基準住所からの正確な距離・所要時間・「最寄り順」は分からない。検索結果に「徒歩◯分」等の記載があっても、それは検索結果ページの基準点（駅など）からの記載であり、予定先の住所からの距離ではないことが多いので、そのまま距離として書かない。距離・所要時間の項目は出力しない。
- **採用フィルタ（重要）**: 候補として採用してよいのは、駐車場の住所・名称に**検索クエリで使った町名・丁目が実際に含まれているもの**だけ。駅前の有名駐車場など、町名が一致しない「その市内のどこか」の結果は、実際の予定先から近いかどうか確認できないため**採用しない**。
  - 町名一致の候補が 3〜5 件程度取れれば、それを使う（重複はまとめる）。
  - 町名一致の候補が 1 件も無い場合は、無理に候補を出さず「Web検索では信頼できる近隣候補が見つからなかった」ことにする（次のステップで「見つからず」と明記する）。郊外・住宅地はこのケースが珍しくない。

### 4-補. 料金の目安（可能であれば）

- 見つかった駐車場名＋「料金」で追加の `WebSearch` / `WebFetch` を行い、目安が取れれば添える。
- 確実な情報が取れない場合は無理に載せず、「料金は要現地確認」と明記する。料金は「可能であれば」の付加情報であり、取れなくても他の情報は返す。

### 5. 予定に追記する

- **書き込みは実データの変更なので、追記する前に必ず内容と対象予定をユーザーに提示し、了承を得てから** `update_event` で説明欄（description）を更新する。
- **既存の説明を消さず、末尾に追記**する。手順は「`get_event` で現在の description を取得 → 末尾に下記ブロックを足した全文を `update_event` の `description` に渡す」。既存本文（顧客情報など）を絶対に落とさないこと。
- 追記フォーマット（この形を守る。距離・所要時間の項目は含めない）:

```
──── 近隣コインパーキング（parking-finder 追記 / YYYY-MM-DD 時点・Web検索の簡易版）────
基準住所: ＜予定の場所欄の住所＞
※Web検索による目安情報です。正確な最寄り順ではないため、訪問前に地図アプリ等で最終確認してください。

1. ＜駐車場名＞
   運営: ＜分かれば。不明なら省略＞
   料金: ＜分かれば。不明なら「要現地確認」＞

2. ＜駐車場名＞
   ...
```

- **町名一致の候補が 1 件も見つからなかった場合**は、上記の代わりに次の形で追記する（存在しない候補をでっち上げない）:

```
──── 近隣コインパーキング（parking-finder 追記 / YYYY-MM-DD 時点・Web検索の簡易版）────
基準住所: ＜予定の場所欄の住所＞
Web検索では信頼できる近隣候補が見つかりませんでした。現地で直接確認してください。
```

- 追記後、何をどの予定に書き込んだかをユーザーに一言で報告する。
- 書き込み権限がない／更新ツールが見つからない場合は、追記はせず結果を会話で提示し、その旨を伝える。

### 6. 「JCOM交通費精算」予定を作成する

一連の処理の締めとして、その日にまとめて「交通費精算」用の予定を作る。

- **対象**: ②で対象にした（住所が入っていた）予定のみ。1 件も無ければこの工程はスキップする。
- **予定の内容**:
  - タイトル: `JCOM交通費精算`
  - カレンダー: 既定の対象カレンダー（その他業務(法人含)。ユーザー指定があればそれ）
  - 日時: **その日の 18:00〜19:00（1 時間、`Asia/Tokyo`）**
  - 説明文（description）: **処理した各予定の住所だけを、開始時刻順に 1 行ずつ列挙する**（駐車場情報や予定名は入れない。住所のみ）。各予定の `location` 欄の値をそのまま使う。
- **説明文の例**（今回の 5 件なら）:

```
埼玉県 八潮市 大曽根817-8
埼玉県 川口市芝下3丁目22-12 エンゼルハイツA 102
埼玉県 川口市 神戸586-3
埼玉県草加市栄町3丁目9-18-01 すみれハウス 102
埼玉県草加市谷塚町1413-8 ウイニング谷塚 202
```

- **重複回避（作成 or 更新）**: 作成前に `list_events` でその日の同カレンダーを確認し、既に `JCOM交通費精算` があれば、新規作成せずその予定を `update_event` で更新する（日時 18:00〜19:00・説明文を上書き）。無ければ `create_event` で新規作成する。
- 作成／更新したことをユーザーに一言で報告する。

## 出力スタイル

- ユーザーには、まず見つかった駐車場候補を上記フォーマットに近い形で分かりやすく提示し、了承を得てから予定に追記する。
- 距離・所要時間は出さない（簡易版のため）。その旨を毎回明記する。
- 住所ありの予定が複数あるときは、予定ごとに見出しを付けて結果をまとめる。住所なしでスキップした予定はその旨だけ簡潔に伝える。

## 使い方（都度・日付指定での呼び出し）

基本の使い方は「日付を指定して都度実行」。自然文でチャットに書くだけでよい。対象カレンダーは既定で「その他業務(法人含)」なので、通常はカレンダー名を省略できる。例:

- 「**7/25 の予定の近くのコインパーキングを探して、予定に追記して**」（基本形）
- 「明日の訪問先の駐車場を調べて予定に書いておいて」
- 「来週月曜の訪問先、探すだけでいい（追記はしないで）」

ポイント:
- **日付は必ず添える**（明日/今日/7/25/来週月曜 など）。日付が曖昧なら確認する。
- カレンダーは既定で「その他業務(法人含)」。別カレンダーなら名前を添える（例:「訪問サポートの…」）。
- 「予定に追記して」まで言えば⑤まで実行、「探すだけ」なら提示のみで止める。追記は実データ変更なので、明示がなければ提示後に確認する。
