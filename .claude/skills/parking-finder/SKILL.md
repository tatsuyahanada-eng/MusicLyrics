# parking-finder

Google カレンダーの予定を起点に、目的地近くの**コインパーキング（時間貸し）**を探して予定に追記するスキル。
用途は「訪問・打ち合わせなどで、その場所に一時的に行き、近くに短時間だけ車を停めたい」ケース。
月極・駐輪場（自転車）・車庫などは目的に合わないので既定で除外する。

## このスキルが行うこと（全体像）

```
① 指定された日付の予定をカレンダーから取得
     ↓
② 「場所（location）」欄に住所が入っている予定だけを対象にする（住所なしはスキップ）
     ↓
③ 基準住所の近くのコインパーキングを検索（名前・住所）※複数可
     ↓
④ 各駐車場について、基準住所からの距離・所要時間を計算
     ↓
⑤ （可能なら）駐車場の料金の目安を補足
     ↓
⑥ 結果を、その予定の説明欄（description）に追記する
     ↓
⑦ その日の 18:00〜19:00 に「JCOM交通費精算」予定を作成し、
   処理した各予定の住所だけを説明文に列挙する（既にあれば更新）
```

## 前提（動かす前に必要なもの）

このスキルは 2 つの外部サービスに依存する。未設定だと動かないので、最初に確認すること。

1. **Google カレンダー コネクタ**（予定の読み取り＋**書き込み**の両方）
2. **Google Maps API キー**（環境変数 `GOOGLE_MAPS_API_KEY`）

セットアップ手順（APIキーの取得場所を含む）は **`references/setup.md`** に詳しく書いてある。
前提が整っていない兆候（下記）が出たら、途中で止めて `references/setup.md` を案内すること。

- カレンダー系の MCP ツールが見つからない → コネクタ未接続
- スクリプトが `GOOGLE_MAPS_API_KEY is not set` を返す → APIキー未設定
- スクリプトが `REQUEST_DENIED` / `API key not valid` / 特定 API の `... is not enabled` を返す → キーが無効か、必要な API が未有効化

## 手順

### 0. 前提の確認

- Google Maps のキーは、まず `echo "${GOOGLE_MAPS_API_KEY:+set}"` で設定有無だけ確認する（値は表示しない）。未設定なら `references/setup.md` を案内して止める。
- カレンダーのツールは名前がコネクタによって変わる。`ToolSearch` で `google calendar events` のように検索し、`list_calendars` / `list_events` / `get_event` / `update_event` / `create_event` に相当するツールを特定する。見つからなければコネクタ未接続として `references/setup.md` を案内する。

### 1. 対象の予定を取得する

- ユーザーが指定した日付（「明日」「7月25日」など）を具体的な日付に解決する。曖昧なら確認する。時刻は指定タイムゾーン（日本なら `Asia/Tokyo`）で解釈する。
- **既定の対象カレンダーは「その他業務(法人含)」**（`o139e347hvc5v9c5a043bh5v18@group.calendar.google.com`）。ユーザーが別のカレンダーを指定した場合はそちらを使う。ID が変わっている可能性もあるので、`list_calendars` で「その他業務」を含む名前のカレンダーを解決してから使うと確実。
- 予定は複数のカレンダーに分かれていることがある。ユーザーが「全部のカレンダー」等と指定した場合は、`list_calendars` の各カレンダーを順に `list_events` で確認する。どのカレンダーか曖昧なら確認する。
- その日の予定を `list_events`（`startTime`/`endTime` にその日の 00:00〜23:59、`orderBy: startTime`）で取得する。

### 2. 対象を「住所が入っている予定」に絞る

- **「場所（location）」欄に住所が入っている予定だけを対象にする。** 場所欄が空の予定は基準地点が無いのでスキップし、スキップした予定名をユーザーに一言伝える（駐車場検索の対象外である旨）。
- 場所欄が施設名や駅名のみでも、そのまま住所としてジオコーディングを試してよい（スクリプトが解決する）。

### 3〜5. コインパーキングを検索し、距離・所要時間を計算する

対象の各予定について `scripts/find_parking.py` を実行する。Geocoding →（コインパーキングの）テキスト検索 → 距離計算をまとめて行い、JSON を返す。

```bash
python3 .claude/skills/parking-finder/scripts/find_parking.py \
  --address "＜予定の場所欄の住所＞" \
  --radius 900 \
  --max 5 \
  --mode walking
```

- 既定で検索クエリは「コインパーキング」。月極・駐輪場・車庫・トレーラー等は名前から自動除外される（`--include-all` で除外を無効化できる）。
- `--radius`: 検索半径（メートル、既定 900）。**結果が 0 件、または少なすぎる場合は半径を段階的に広げて再実行する**（例: 900 → 1500 → 2200）。郊外・住宅地は時間貸しがまばらなことがある。既定を900mにしているのは、実際の徒歩距離ベースの絞り込みで600mだと弾かれるケースが多く、無駄な再実行（＝クォータの無駄遣い）につながっていたため。
- `--mode`: `walking`（既定）＝駐車場から目的地まで歩く前提の距離・時間。半径を大きく広げた郊外ケースなど、車移動基準の方が実態に合うときは `driving` にする。
- `--max`: 取得件数（既定 5）。「複数あってよい」ので既定のままでよい。ユーザー指定があれば従う。
- 出力は半径内・距離の近い順にソートされた駐車場配列（`name`・`address`・`distance`・`duration`）。`parking` が空で `note` が付く場合は、その指示どおり `--radius` を広げて再実行する。**ただし再実行は Distance Matrix の要素クォータを追加消費するので、本当に必要な場合だけにする**（`900` で 1 件も無ければ広げる。すでに候補が出ているのに念のため広げ直す、といったことはしない）。
- スクリプトが `error` キーを返したら内容に従って対処する（キー未設定 → `references/setup.md`）。
- 複数の予定を処理するときは、住所ごとに 1 回ずつ実行する。1 回の実行で Distance Matrix の要素を最大 8 件（`--max + 3` と 8 の大きい方）消費する。**Distance Matrix API のクォータは「1日あたりの要素（elements）数」で切られていることが多く、実測で 1 日 100 要素程度と少ない**。5 件訪問＋区間計算6要素で通常 50〜60 要素程度に収まるが、同じ日に複数日分をまとめて処理する場合は消費が倍増するので注意する。

### 5-補. 料金の目安（可能であれば）

- Google Maps API は駐車料金を返さない。必要なら、駐車場名＋「料金」で `WebSearch` / `WebFetch` を使って目安を補足する。
- 確実な情報が取れない場合は無理に載せず、「料金は要現地確認」と明記する。料金は「可能であれば」の付加情報であり、取れなくても他の情報は返す。

### 6. 予定に追記する

- **書き込みは実データの変更なので、追記する前に必ず内容と対象予定をユーザーに提示し、了承を得てから** `update_event` で説明欄（description）を更新する。
- **既存の説明を消さず、末尾に追記**する。手順は「`get_event` で現在の description を取得 → 末尾に下記ブロックを足した全文を `update_event` の `description` に渡す」。既存本文（顧客情報など）を絶対に落とさないこと。
- 追記フォーマット（この形を守る）:

```
──── 近隣コインパーキング（parking-finder 追記 / YYYY-MM-DD 時点）────
基準住所: ＜base_address＞

1. ＜駐車場名＞
   住所: ＜住所＞
   距離: ＜distance＞（＜mode: 徒歩/車＞ ＜duration＞）
   料金: ＜分かれば。不明なら「要現地確認」＞

2. ＜駐車場名＞
   ...
```

- 追記後、何をどの予定に書き込んだかをユーザーに一言で報告する。
- 書き込み権限がない／更新ツールが見つからない場合は、追記はせず結果を会話で提示し、その旨を伝える。

### 7. 「JCOM交通費精算」予定を作成する

一連の処理の締めとして、その日にまとめて「交通費精算」用の予定を作る。

- **対象**: ②で対象にした（住所が入っていた）予定のみ。1 件も無ければこの工程はスキップする。
- **予定の内容**:
  - タイトル: `JCOM交通費精算`
  - カレンダー: 既定の対象カレンダー（その他業務(法人含)。ユーザー指定があればそれ）
  - 日時: **その日の 18:00〜19:00（1 時間、`Asia/Tokyo`）**
  - 説明文（description）は次の3ブロックで構成する（この順番・空行を守る）:
    1. **住所リスト**: 処理した各予定の住所だけを、開始時刻順に 1 行ずつ列挙する（駐車場情報や予定名は入れない。住所のみ）。各予定の `location` 欄の値をそのまま使う。
    2. **区間ごとの移動距離・所要時間**: 自宅（`埼玉県越谷市東大沢1-22-4`）→訪問先1→訪問先2→…→訪問先N→自宅、という一筆書きの区間（合計 N+1 区間）を計算する。
       - **重要（クォータの単位に注意）**: Distance Matrix API のクォータは「1日あたりのリクエスト回数」ではなく「**要素（elements）数 = 出発地の数 × 目的地の数**」で切られている（実測値: 1日100要素程度と非常に少ない）。区間をまとめて1回のリクエストで呼ぶと、出発地N+1件×目的地N+1件＝**(N+1)²要素**を消費してしまい（例: 5件なら36要素）、かえって無駄になる。
       - **必ず区間ごとに1回、出発地1件・目的地1件（＝1要素）のリクエストを N+1 回行う**こと。1回のリクエストで複数区間をまとめない。
       - 例（curl、1区間ぶん）:
         ```bash
         curl -sS -G "https://maps.googleapis.com/maps/api/distancematrix/json" \
           --data-urlencode "origins=＜区間の出発地住所＞" \
           --data-urlencode "destinations=＜区間の目的地住所＞" \
           --data-urlencode "mode=driving" --data-urlencode "language=ja" \
           --data-urlencode "key=${GOOGLE_MAPS_API_KEY}"
         ```
         これを「自宅→訪問先1」「訪問先1→訪問先2」…「訪問先N→自宅」の順に N+1 回実行する（合計 N+1 要素）。
       - 結果を `自宅→訪問先1　距離（車 所要時間）` / `訪問先N→訪問先N+1　距離（車 所要時間）` / `訪問先N→自宅　距離（車 所要時間）`（Nは最後の訪問先番号）の形式で1行ずつ出す。
    3. **参考リンク**: `https://myse-style.com/AI-TOOL/RouteSearch/` を1行で。
- **説明文の例**（今回の 5 件なら）:

```
埼玉県 八潮市 大曽根817-8
埼玉県 川口市芝下3丁目22-12 エンゼルハイツA 102
埼玉県 川口市 神戸586-3
埼玉県草加市栄町3丁目9-18-01 すみれハウス 102
埼玉県草加市谷塚町1413-8 ウイニング谷塚 202

自宅→訪問先1　6.5 km（車 15分）
訪問先1→訪問先2　3.2 km（車 9分）
訪問先2→訪問先3　1.8 km（車 6分）
訪問先3→訪問先4　5.1 km（車 14分）
訪問先4→訪問先5　2.4 km（車 7分）
訪問先5→自宅　7.8 km（車 18分）

https://myse-style.com/AI-TOOL/RouteSearch/
```

- **重複回避（作成 or 更新）**: 作成前に `list_events` でその日の同カレンダーを確認し、既に `JCOM交通費精算` があれば、新規作成せずその予定を `update_event` で更新する（日時 18:00〜19:00・説明文を上書き）。無ければ `create_event` で新規作成する。
- 作成／更新したことをユーザーに一言で報告する。

## 出力スタイル

- ユーザーには、まず見つかった駐車場を上記フォーマットに近い形で分かりやすく提示し、了承を得てから予定に追記する。
- 距離・所要時間は API の返した日本語表記（例「450 m」「徒歩 6 分」）をそのまま使う。
- 住所ありの予定が複数あるときは、予定ごとに見出しを付けて結果をまとめる。住所なしでスキップした予定はその旨だけ簡潔に伝える。

## 使い方（都度・日付指定での呼び出し）

基本の使い方は「日付を指定して都度実行」。自然文でチャットに書くだけでよい。対象カレンダーは既定で「その他業務(法人含)」なので、通常はカレンダー名を省略できる。例:

- 「**7/25 の予定の近くのコインパーキングを探して、予定に追記して**」（基本形）
- 「明日の訪問先の駐車場を調べて予定に書いておいて」
- 「今日の午後の予定だけ、車移動で半径800mで探して」
- 「来週月曜の訪問先、探すだけでいい（追記はしないで）」

ポイント:
- **日付は必ず添える**（明日/今日/7/25/来週月曜 など）。日付が曖昧なら確認する。
- カレンダーは既定で「その他業務(法人含)」。別カレンダーなら名前を添える（例:「訪問サポートの…」）。
- 「予定に追記して」まで言えば⑥まで実行、「探すだけ」なら提示のみで止める。追記は実データ変更なので、明示がなければ提示後に確認する。
- 半径や徒歩/車の希望があれば伝える（例:「半径800m」「車移動で」「徒歩5分以内」）。

## 補足ファイル

- `scripts/find_parking.py` — コインパーキング検索＋距離計算の本体（上記コマンドで実行）。`--query` で検索語、`--include-all` で除外解除。
- `references/setup.md` — Google カレンダー接続と **Google Maps API キーの取得場所・手順**、環境変数の設定方法、無料枠・課金防止設定。前提が未整備のときはここを案内する。
