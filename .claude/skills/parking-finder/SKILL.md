# parking-finder

Google カレンダーの予定を起点に、目的地近くの**コインパーキング（時間貸し）**を探して予定に追記するスキル。
用途は「訪問・打ち合わせなどで、その場所に一時的に行き、近くに短時間だけ車を停めたい」ケース。
月極・駐輪場（自転車）・車庫などは目的に合わないので既定で除外する。

## このスキルが行うこと（全体像）

```
① 指定された日付の予定をカレンダーから取得
     ↓
② 「場所（location）」欄に住所が入っている予定だけを対象にする（住所なしはスキップ）
     ↓
③ 基準住所の近くのコインパーキングを検索（名前・住所）※複数可
     ↓
④ 各駐車場について、基準住所からの距離・所要時間を計算
     ↓
⑤ （可能なら）駐車場の料金の目安を補足
     ↓
⑥ 結果を、その予定の説明欄（description）に追記する
```

## 前提（動かす前に必要なもの）

このスキルは 2 つの外部サービスに依存する。未設定だと動かないので、最初に確認すること。

1. **Google カレンダー コネクタ**（予定の読み取り＋**書き込み**の両方）
2. **Google Maps API キー**（環境変数 `GOOGLE_MAPS_API_KEY`）

セットアップ手順（APIキーの取得場所を含む）は **`references/setup.md`** に詳しく書いてある。
前提が整っていない兆候（下記）が出たら、途中で止めて `references/setup.md` を案内すること。

- カレンダー系の MCP ツールが見つからない → コネクタ未接続
- スクリプトが `GOOGLE_MAPS_API_KEY is not set` を返す → APIキー未設定
- スクリプトが `REQUEST_DENIED` / `API key not valid` / 特定 API の `... is not enabled` を返す → キーが無効か、必要な API が未有効化

## 手順

### 0. 前提の確認

- Google Maps のキーは、まず `echo "${GOOGLE_MAPS_API_KEY:+set}"` で設定有無だけ確認する（値は表示しない）。未設定なら `references/setup.md` を案内して止める。
- カレンダーのツールは名前がコネクタによって変わる。`ToolSearch` で `google calendar events` のように検索し、`list_calendars` / `list_events` / `get_event` / `update_event` に相当するツールを特定する。見つからなければコネクタ未接続として `references/setup.md` を案内する。

### 1. 対象の予定を取得する

- ユーザーが指定した日付（「明日」「7月25日」など）を具体的な日付に解決する。曖昧なら確認する。時刻は指定タイムゾーン（日本なら `Asia/Tokyo`）で解釈する。
- 予定は複数のカレンダーに分かれていることがある。まず `list_calendars` でカレンダー一覧を取り、ユーザーが対象カレンダー（例:「その他業務」）を指定していればそれを、指定がなければ心当たりのカレンダーを順に `list_events` で確認する。どのカレンダーか曖昧なら確認する。
- その日の予定を `list_events`（`startTime`/`endTime` にその日の 00:00〜23:59、`orderBy: startTime`）で取得する。

### 2. 対象を「住所が入っている予定」に絞る

- **「場所（location）」欄に住所が入っている予定だけを対象にする。** 場所欄が空の予定は基準地点が無いのでスキップし、スキップした予定名をユーザーに一言伝える（駐車場検索の対象外である旨）。
- 場所欄が施設名や駅名のみでも、そのまま住所としてジオコーディングを試してよい（スクリプトが解決する）。

### 3〜5. コインパーキングを検索し、距離・所要時間を計算する

対象の各予定について `scripts/find_parking.py` を実行する。Geocoding →（コインパーキングの）テキスト検索 → 距離計算をまとめて行い、JSON を返す。

```bash
python3 .claude/skills/parking-finder/scripts/find_parking.py \
  --address "＜予定の場所欄の住所＞" \
  --radius 600 \
  --max 5 \
  --mode walking
```

- 既定で検索クエリは「コインパーキング」。月極・駐輪場・車庫・トレーラー等は名前から自動除外される（`--include-all` で除外を無効化できる）。
- `--radius`: 検索半径（メートル、既定 600）。**結果が 0 件、または少なすぎる場合は半径を段階的に広げて再実行する**（例: 600 → 1200 → 2000）。郊外・住宅地は時間貸しがまばらなことがある。
- `--mode`: `walking`（既定）＝駐車場から目的地まで歩く前提の距離・時間。半径を大きく広げた郊外ケースなど、車移動基準の方が実態に合うときは `driving` にする。
- `--max`: 取得件数（既定 5）。「複数あってよい」ので既定のままでよい。ユーザー指定があれば従う。
- 出力は半径内・距離の近い順にソートされた駐車場配列（`name`・`address`・`distance`・`duration`）。`parking` が空で `note` が付く場合は、その指示どおり `--radius` を広げて再実行する。
- スクリプトが `error` キーを返したら内容に従って対処する（キー未設定 → `references/setup.md`）。
- 複数の予定を処理するときは、住所ごとに 1 回ずつ実行する（1 回の実行 ≒ 3 API 呼び出し。無料枠に対して十分小さい）。

### 5-補. 料金の目安（可能であれば）

- Google Maps API は駐車料金を返さない。必要なら、駐車場名＋「料金」で `WebSearch` / `WebFetch` を使って目安を補足する。
- 確実な情報が取れない場合は無理に載せず、「料金は要現地確認」と明記する。料金は「可能であれば」の付加情報であり、取れなくても他の情報は返す。

### 6. 予定に追記する

- **書き込みは実データの変更なので、追記する前に必ず内容と対象予定をユーザーに提示し、了承を得てから** `update_event` で説明欄（description）を更新する。
- **既存の説明を消さず、末尾に追記**する。手順は「`get_event` で現在の description を取得 → 末尾に下記ブロックを足した全文を `update_event` の `description` に渡す」。既存本文（顧客情報など）を絶対に落とさないこと。
- 追記フォーマット（この形を守る）:

```
──── 近隣コインパーキング（parking-finder 追記 / YYYY-MM-DD 時点）────
基準住所: ＜base_address＞

1. ＜駐車場名＞
   住所: ＜住所＞
   距離: ＜distance＞（＜mode: 徒歩/車＞ ＜duration＞）
   料金: ＜分かれば。不明なら「要現地確認」＞

2. ＜駐車場名＞
   ...
```

- 追記後、何をどの予定に書き込んだかをユーザーに一言で報告する。
- 書き込み権限がない／更新ツールが見つからない場合は、追記はせず結果を会話で提示し、その旨を伝える。

## 出力スタイル

- ユーザーには、まず見つかった駐車場を上記フォーマットに近い形で分かりやすく提示し、了承を得てから予定に追記する。
- 距離・所要時間は API の返した日本語表記（例「450 m」「徒歩 6 分」）をそのまま使う。
- 住所ありの予定が複数あるときは、予定ごとに見出しを付けて結果をまとめる。住所なしでスキップした予定はその旨だけ簡潔に伝える。

## 使い方（定期利用の呼び出し例）

このスキルは自然文で呼び出せる。例:

- 「明日の予定の近くのコインパーキングを探して、予定に追記して」
- 「7/25 の『その他業務』カレンダーの訪問先について、近くの駐車場を調べて」
- 「今日の午後の予定、住所が入ってるものだけ駐車場を検索して」
- 「来週月曜の訪問先の駐車場、徒歩5分以内で探して予定に書いておいて」

ポイント:
- 日付（明日/今日/具体日）と、必要ならカレンダー名を添えると確実。
- 「予定に追記して」まで言えば⑥まで実行、「探すだけ」なら提示のみで止める。
- 半径や徒歩/車の希望があれば伝える（例:「半径800m」「車移動で」）。

## 補足ファイル

- `scripts/find_parking.py` — コインパーキング検索＋距離計算の本体（上記コマンドで実行）。`--query` で検索語、`--include-all` で除外解除。
- `references/setup.md` — Google カレンダー接続と **Google Maps API キーの取得場所・手順**、環境変数の設定方法、無料枠・課金防止設定。前提が未整備のときはここを案内する。
