# Case By Case — ツリー型 作業マニュアル（サーバーDB共有版）

大項目を選ぶと枝分かれし、最終的な作業手順まで案内する「チャットボット風」のツリーマニュアルです。
**サーバー（PHP + MySQL）に接続すると、みんなの入力が1つのマニュアルとして蓄積・共有**されます。
画像の貼り付けにも対応します。未接続でもこの端末内（localStorage）だけで動作します。

## 仕組み（データの一元管理）

- **サーバー（DB）を唯一の正データ**とし、項目（ノード）ごとに 追加 / 更新 / 削除 / 並び替え します。
  「ファイル丸ごと上書き」をしないため、複数人が同時に編集しても**他の人の入力を消しません**。
- 各端末は起動時にサーバーから読み込み、編集は即サーバーへ反映。
  「最新に更新」ボタン＋約30秒ごとの自動更新で、他端末の変更も表示されます。
- テーブルは1つ（`nodes`）。列は将来の拡張にもそのまま使えます。

| 列 | 意味 |
|---|---|
| `id` | ノードの一意ID |
| `parent_id` | 親のID（空＝大項目/カテゴリ） |
| `sort_order` | 同じ親の中での並び順 |
| `title` | 選択肢に表示される項目名 |
| `body` | 説明・手順（Markdown風。画像 `![](uploads/xxx.jpg)` も可） |
| `updated_at` / `created_at` | 更新・作成時刻（ミリ秒） |

## ファイル構成

| ファイル | 役割 |
|---|---|
| `manual.html` / `manual.css` / `manual.js` | アプリ本体 |
| `manifest.webmanifest` / `sw.js` / `icon*.png/svg` | PWA（インストール・オフライン） |
| `logo-default.png` | ヘッダーの既定ロゴ画像（管理者が入れ替え可能。詳細は「ヘッダーロゴ」を参照） |
| `api.php` | サーバーAPI（DB操作・画像アップロード） |
| `db.php` | DB接続・テーブル自動作成（PDO） |
| `config.sample.php` | 設定サンプル（→ `config.php` にコピー） |
| `data/` | SQLite利用時のDB置き場（`.htaccess`で直接アクセス禁止） |
| `uploads/` | アップロード画像の保存先（`.htaccess`でスクリプト実行禁止） |
| `backups/` | 毎日自動作成される完全バックアップ（JSON）の置き場（`.htaccess`で直接アクセス禁止） |

## ロリポップ! への設置手順

### 1. データベースを作成
ユーザー専用ページ →「サーバーの管理・設定」→「データベース」→「データベース作成」。
表示される **サーバー / データベース名 / ユーザー名 / パスワード** を控えます。
（※ロリポップはMySQLです。PostgreSQLは提供されていません）

### 2. PHPバージョン
ユーザー専用ページ →「PHP設定」で **PHP 7.4 以上** を選択。

### 3. ファイルをアップロード
本一式を公開フォルダ（例: `/casebycase/`）へFTPでアップロード。

### 4. config.php を作成
`config.sample.php` を **`config.php`** にコピーし、DB情報を記入：

```php
define('DB_DRIVER', 'mysql');
define('DB_HOST', 'mysql-XXXXX.phy.lolipop.lan'); // 手順1のサーバー名
define('DB_NAME', 'LAA0000000-casebycase');       // データベース名
define('DB_USER', 'LAA0000000');                  // ユーザー名
define('DB_PASS', '設定したパスワード');
define('API_TOKEN', '好きな合言葉');               // 公開URLでは必ず設定
```

### 5. 書き込み権限
FTPソフトで、`uploads/` フォルダのパーミッションを **705（必要なら 707）** に設定。
（テーブルは初回アクセス時に自動作成されます）

### 6. 開く
`https://お使いのドメイン/casebycase/`（または `manual.html`）を開く。
編集モード →「サーバー連携」で **DB接続済み（共有中）** と表示されれば成功です。
`API_TOKEN` を設定した場合は、編集する人が「編集トークン」に同じ合言葉を入力します。

## ログイン（アクセス制限）と自動ログアウト

このアプリは「ログインした人だけが内容を見られる」ことを前提にしています。

### サーバー側のログイン設定（必須）
ログイン（ID・パスワード）は **レンタルサーバーの「アクセス制限（Basic認証）」** で行います。
ロリポップ等の管理画面で、アプリを置いた **公開フォルダ全体**（`manual.html` と `api.php` を含む）に
アクセス制限を設定してください。これを設定しないと、誰でも中身を見られてしまいます。

- ログインしていない（キャンセルした）場合、アプリは中身を一切表示せず「ログインが必要です」画面になります。
- この端末に前回の内容が残っていても、**ログインしDBに接続できるまでは表示しません**（古いデータを見せません）。

### 自動ログアウト・手動ログアウト
- 画面下部の **「🔒 ログアウト」** で、いつでも手動ログアウトできます。
- **一定時間（既定9時間）操作がない**と、自動的にログアウトします。
  操作（クリック・キー入力・タッチ）のたびに時間はリセットされます。
- 「最終操作からの経過時間」で判定するため、スマホでアプリを閉じていた／端末がスリープしていた
  場合でも、**9時間以上たっていれば次に開いたときに自動的にログアウト**します（タイマーが
  端末側で止まっても取りこぼしません）。この判定は端末内で完結し、サーバーへは通信しません。
- ログアウトすると「ログアウトしました」画面になり、**「ログイン」ボタン**で再読み込み →
  サーバーのログイン画面から入り直します。パスワードを入れずにキャンセルした場合は、
  中身は表示されません。
- 自動ログアウトまでの時間を変えたい場合は、URL に `?idlemin=60`（60分）のように付けるか、
  ブラウザの localStorage に `treeManual.idleMin.v1`（分）を設定します。

> Basic認証の資格情報はブラウザが記憶するため、ログアウト後に同じブラウザで「ログイン」すると
> 再入力を求められないことがあります。確実に入力し直したい場合は、ブラウザ（またはPWAアプリ）を
> 一度完全に閉じてから開き直してください。

## アプリ内ログインと、IDごとのページ閲覧権限

サーバーのアクセス制限（Basic認証）の内側に、**アプリ独自のログイン**を設けています。
これにより「どのIDがどの大項目（カテゴリ）を閲覧できるか」を管理者が設定できます。

### ログインの仕組み
- 画面を開くと（Basic認証を通過後）**アプリのログイン画面**が出ます。ID・パスワードでログインします。
- **管理者**：`config.php` の `ADMIN_PW`（管理者パスワード）でログインします（IDは任意の文字でOK）。
  全ページの閲覧・編集・ユーザー権限設定ができます。
- **一般ユーザー**：管理者が作成したID/パスワードでログインします。**許可された大項目だけ**が表示されます
  （許可外のカテゴリはサーバー側でも渡されないため、URL直打ち等でも見られません）。
- 一定時間（既定9時間）操作がないと自動ログアウトします。画面下部「🔒 ログアウト」でも手動ログアウトできます。

### 管理者による権限設定
1. 管理者でログイン → 上部「修正」→ ツールバーの **「👥 ユーザー権限」** を開く。
2. ユーザーを追加：**ID・名前・パスワード**を入力し、**閲覧できる大項目（カテゴリ）にチェック**して保存。
   - **名前** は、その人が項目を追加・更新したときの**登録者名として自動的に記録**されます（本人が入力する必要はありません）。
   - 例：ユーザーA＝「大項目1」と「大項目3」、ユーザーB＝「大項目2」だけ、のように振り分け。
   - 「管理者にする」にチェックすると、そのIDは全ページ閲覧・編集ができます。
3. 既存ユーザーは「編集」で名前・権限変更・**パスワードの再設定**、「削除」で削除できます。
   - 管理者は、**どのユーザーのパスワードでも**「編集」→「パスワード」欄に新しい値を入れて保存すれば変更できます（現在のパスワードは不要）。

> ログインすると、画面**上部にログイン中の名前**が小さく表示されます。

### 本人によるパスワード変更

ログインした本人が、自分のパスワードを変更できます。

1. 画面下のフッターにある **「🔑 パスワード変更」** を押す。
2. **現在のパスワード**と**新しいパスワード（4文字以上・確認用に2回）** を入力して「変更する」。

> このボタンは、**ユーザー登録のあるアカウント**でログインしているときだけ表示されます。
> 管理者パスワード（`ADMIN_PW`）でログインしている場合は表示されません（その場合は `config.php` の `ADMIN_PW` を変更してください）。
> 権限は **大項目（カテゴリ）単位** です。許可した大項目の中の子項目はすべて閲覧できます。

#### 新しく大項目を追加したときの初期の閲覧権限

- **管理者**：新しく追加した大項目も、追加した時点で**自動的に閲覧・編集できます**（管理者は常に全ページにアクセスできます）。
- **管理者以外**：新しく追加した大項目は、**最初は表示されません**。管理者が「👥 ユーザー権限」でそのユーザーに許可を与えて初めて表示されます。
- 大項目を追加したあと「👥 ユーザー権限」を開くと、**追加した大項目がすぐにチェック一覧に出ます**ので、その場で割り当てられます。

### 登録者名（自動記録）

- 項目を**新規作成**すると、その人の名前が **作成者（`created_by`）** として記録され、**以降は変わりません**（ずっと残ります）。
- 項目を**更新**すると、**更新者（`updated_by`）** がそのつど**上書き**されます（最後に更新した人の名前になります）。
- 名前は**ログイン中のアカウントの名前から自動で入り**、サーバー側でも同じ値に確定するため、手入力での付け替えはできません。
> 「在庫管理」はカテゴリ単位の権限対象外です。表示・非表示は下記のトグルで管理者が全体に対して切り替えます（初期状態は**非表示**）。

### 在庫管理の表示ON/OFF（管理者のみ）

在庫管理タイルを、全端末に対してまとめて表示／非表示にできます（初期状態は**非表示**）。

1. 管理者でログイン → 上部「修正」を開く。
2. 「📦 在庫管理を表示する」トグルをONにすると、案内モードの大項目一覧に「在庫管理」タイルが表示されます。OFFにすると全員から非表示になり、検索結果にも在庫商品は出なくなります。

> この設定は全端末で共有されます（サーバーの `app_settings` に保存）。切り替えられるのは管理者のみです。

## 同時アクセス時の安定性（DB接続）

複数の人が同時にアクセスしても「データベースに接続できません（`[1040] Too many connections`）」が出にくいよう、次の工夫を入れています。

- **テーブル作成チェックを毎回実行しない**：スキーマの初期化（`CREATE TABLE …` などの十数個のSQL）は、**バージョンが変わったとき一度だけ**実行します。判定は `data/.schema-version` という小さな目印ファイルで行います（`data/` は外部から直接アクセスできません）。これにより通常の1リクエストが軽くなり、DB接続を握る時間が短くなります。
- **一時的な接続数オーバーを自動リトライ**：接続時に `Too many connections` になった場合、サーバー側・アプリ側の両方で**少し待って数回だけ自動的に再試行**します。瞬間的なアクセス集中を吸収し、いきなりエラー画面を出しません。

> それでも頻発する場合は、レンタルサーバー側のMySQLの同時接続数の上限（`max_connections` / `max_user_connections`）が要因です。契約プランの上限をご確認ください。
> スキーマを変更したとき（列やテーブルの追加）は `db.php` の `CBC_SCHEMA_VERSION` を上げると、各サーバーで初回アクセス時に一度だけ再初期化されます。

## AI（Google Gemini）で探す・要約する（任意）

自然文で項目を探す「AIで探す」と、項目の本文を要約する「AI要約」を使えます。
**APIキーを設定したときだけ**この機能が表示されます（未設定なら従来どおり非表示）。

### 設定手順
1. **APIキーを取得**：Google AI Studio（`https://aistudio.google.com/apikey`）で無料のAPIキーを発行します。
2. **config.php に記入**：
   ```php
   define('GEMINI_API_KEY', 'AIza…');            // 取得したキー
   define('GEMINI_MODEL',   'gemini-2.5-flash');  // 使うモデル（例: gemini-2.5-flash / gemini-flash-latest）
   ```
3. アプリを開き直すと、上部「検索」内に **「✨ AIで探す」**、項目の右上に **「✨ AI要約」** が表示されます。

### 仕組みと注意
- **APIキーはサーバー内（config.php）だけ**で使い、ブラウザ（利用者）には渡しません。
  画面からのAI要求は一度 `api.php` が受け、サーバーがGeminiへ問い合わせます。
- **AIを使うと、その項目の本文（や項目一覧）がGoogleのAPIへ送信されます**（要約・検索のため）。
  社外に出せない内容がある場合は、AI機能を使わない（キーを設定しない）でください。
- サーバー（PHP）から **外部へのHTTPS通信（`curl` など）** が必要です。ロリポップは既定で利用できます。
- 利用はGeminiの**無料枠／従量課金**の対象です（お使いのGoogleアカウントの契約に従います）。
- AIの回答は自動生成のため、**最終的な正確さは元の項目でご確認ください**。
- **モデル名エラー**（`... is not found for API version v1beta ...` や `... is no longer available ...`）
  が出る場合は、指定モデルがそのキーで使えない（廃止された）状態です。`GEMINI_MODEL` を
  `gemini-2.5-flash` などに変更してください。なお本アプリは、使えない／廃止されたモデルのときは
  自動で他の候補（2.5-flash 等）を試し、成功したモデルを記憶して次回から直接使います
  （Googleが将来モデルを廃止しても、次にAIを使ったときに自動で切り替わります）。

### 「AIで探す」の探し方（会話文で質問してOK）
- 「〇〇の交換手順を知りたい」のように、**人に話しかけるような自然な言い方**で質問できます。
  キーワードが本文と完全一致していなくても、質問の意図・同義語・関連する製品名/型番/略称・
  言い換えを考慮して、AIが関連度の高い項目を最大8件まで探します。
- **AIが「該当なし」と判断したときは、自動的にキーワードの部分一致でも探し直します**
  （一覧に **🔍 キーワード** バッジで表示され、AIによる意味検索とは区別されます）。
  製品名や型番など、本文に**そのままの文字列**が含まれている場合はここで見つかります。
- それでも見つからないときは、本当に該当する項目が無いか、権限で見えない状態です。
  言い方を変える、キーワードを短くする（例：型番だけにする）などをお試しください。

### AIによるまとめ（回答の要約）
- AIが**意味検索で見つけた**とき（🔍キーワードのみの一致を除く）は、一覧の**上部に「✨ AIによるまとめ」**として、
  見つかった項目の内容をもとにした**質問への回答文**を表示します。項目を1件ずつ開かなくても、
  まず知りたいことの要点（実際の手順があれば番号付き手順として）をつかめます。
  - まとめは、関連度上位**3件**の項目の**本文全体**（検索一覧より広い範囲・1件あたり最大2000文字）を根拠に作成されます。
  - まとめの下に**「参照した項目」**として、根拠にした項目名をボタンで表示します。**クリックするとその項目をそのまま開けます**。
    まとめの内容が実際の手順と一致しているか、その場で確認できます。
  - 関連項目に書かれていないことは推測で補わない・分からなければ正直にそう書く、よう指示しています
    （とはいえAIの生成物のため、重要な作業の前には参照した項目の原文も必ずご確認ください）。
  - まとめの生成に失敗しても（AI側の一時的な混雑等）、**項目の一覧自体は通常どおり表示されます**。
  - キーワードの部分一致だけで見つかった項目は、AIが内容を理解して選んだものではないため、まとめは作成しません。
- 検索欄の右上「💡 入力のコツ」を押すと、AIが要約・検索しやすくなる**書き方のヒント**が開きます
  （見出しに `# `、箇条書きに `- ` を使う、製品名は正式名称で書く、注意点には目印を付ける、など）。
  これらの記法は**編集画面の本文入力でそのまま使えます**（実際に見出し・箇条書きとして表示されます）。
- **AI検索がタイムアウトする場合**：サーバーからGoogleのAPIへの通信が遅い／不安定な環境向けに、
  通信の待ち時間を伸ばし（約40秒）、失敗時は自動で1回だけ再試行するようにしています。
  それでも「AIサーバーに接続できません」が続く場合は、レンタルサーバーから外部HTTPS通信
  （`generativelanguage.googleapis.com`）がブロックされていないか、契約プランやサポートにご確認ください。

## サーバー移行（別のレンタルサーバーへの引っ越し）手順

別のレンタルサーバーへ本アプリを譲渡・引っ越しする場合の手順です。
**新しいサーバーには MySQL のテーブルが存在しないため、テーブルの新規作成が必要になります。**
テーブルは初回アクセス時に `db.php` が自動作成しますが、権限の都合で自動作成できない環境もあるため、
下記に **手動で作成する CREATE TABLE 文** も用意しています。

### 1. 移行先サーバーに必要な環境

| 項目 | 要件 |
|---|---|
| PHP | **7.4 以上**（8.x 推奨） |
| データベース | **MySQL 5.7 以上 / 8.x**（PostgreSQL も可。SQLite も可） |
| PHP拡張 | `pdo`, `pdo_mysql`（MySQL利用時）, `mbstring`, `fileinfo`, `json`（AI機能を使う場合は `curl` も） |
| Webサーバー | Apache（`.htaccess` が有効なこと）。Nginx等の場合は `uploads/` でのPHP実行禁止と `data/` の直接アクセス禁止を各自設定 |
| 通信 | **HTTPS**（PWA・カメラ/貼り付け等のため必須） |
| 書き込み権限 | `uploads/` フォルダに書き込み可（705 / 707 など） |

### 2. 引っ越し先へ運ぶファイル

FTP等で **アプリ一式** を新サーバーの公開フォルダへアップロードします。

- `manual.html` / `manual.css` / `manual.js`
- `manifest.webmanifest` / `sw.js` / `icon*.svg` / `icon*.png`
- `api.php` / `db.php`
- `config.sample.php`（`config.php` は移行先で新しく作成します）
- `uploads/`（**中の画像・添付ファイルごと** 移すと、既存本文の画像が引き続き表示されます）
- `vendor/`（Excel入出力用ライブラリ）

> `config.php` には旧サーバーのDBパスワード等が入っているため、**そのままは持ち込まず**、
> 移行先で新しいDB情報を入れて作り直してください（次項）。

### 3. 移行先の config.php を作成

移行先で `config.sample.php` を **`config.php`** にコピーし、**新しいサーバーのDB情報**を記入します。

```php
define('DB_DRIVER', 'mysql');
define('DB_HOST', '新サーバーのDBホスト');
define('DB_NAME', '新しいデータベース名');
define('DB_USER', '新しいユーザー名');
define('DB_PASS', '新しいパスワード');   // 移行先で設定した値
define('API_TOKEN', '好きな合言葉');      // 公開URLでは必ず設定
```

### 4. MySQL のテーブルを新規作成

移行先のMySQLには **テーブルが存在しません**。次のいずれかで作成します。

**方法A（かんたん・推奨）: 自動作成**
`config.php` を正しく設定した状態で `manual.html` を一度開くと、`db.php` が
`nodes` / `inv_items` / `inv_logs` / `app_settings` / `users` / `sessions` / `trips` の各テーブルを自動で作成します。特別な操作は不要です。

**方法B: 手動でSQLを実行**
phpMyAdmin 等で下記SQLを実行して、テーブルを作成しておくこともできます
（レンタルサーバーの権限で自動作成に失敗する場合や、事前に用意したい場合に使用）。

```sql
-- ツリー（案内モード）の各項目
CREATE TABLE IF NOT EXISTS nodes (
  id         VARCHAR(40)  NOT NULL PRIMARY KEY,
  parent_id  VARCHAR(40)  NULL,
  sort_order INT          NOT NULL DEFAULT 0,
  title      VARCHAR(255) NOT NULL,
  body       MEDIUMTEXT   NULL,
  created_by VARCHAR(120) NULL,
  updated_by VARCHAR(120) NULL,
  lock_hash  VARCHAR(255) NULL,
  updated_at BIGINT       NOT NULL DEFAULT 0,
  created_at BIGINT       NOT NULL DEFAULT 0,
  INDEX idx_parent (parent_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 在庫管理：品目
CREATE TABLE IF NOT EXISTS inv_items (
  id         VARCHAR(40)  NOT NULL PRIMARY KEY,
  name       VARCHAR(255) NOT NULL,
  model      VARCHAR(255) NULL,
  qty        INT          NOT NULL DEFAULT 0,
  note       VARCHAR(255) NULL,
  sort_order INT          NOT NULL DEFAULT 0,
  created_at BIGINT       NOT NULL DEFAULT 0,
  updated_at BIGINT       NOT NULL DEFAULT 0
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 在庫管理：入出庫の履歴
CREATE TABLE IF NOT EXISTS inv_logs (
  id         VARCHAR(40)  NOT NULL PRIMARY KEY,
  item_id    VARCHAR(40)  NOT NULL,
  action     VARCHAR(20)  NOT NULL,
  qty        INT          NOT NULL DEFAULT 0,
  balance    INT          NOT NULL DEFAULT 0,
  person     VARCHAR(120) NULL,
  note       VARCHAR(255) NULL,
  created_at BIGINT       NOT NULL DEFAULT 0,
  INDEX idx_inv_item (item_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- アプリ共通設定（ピン留めを全端末で共有）
CREATE TABLE IF NOT EXISTS app_settings (
  k VARCHAR(64) NOT NULL PRIMARY KEY,
  v MEDIUMTEXT  NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- アプリ内ログイン：ユーザー（許可カテゴリ・登録者名を保持）
CREATE TABLE IF NOT EXISTS users (
  username     VARCHAR(64)  NOT NULL PRIMARY KEY,
  display_name VARCHAR(120) NULL,
  pass_hash    VARCHAR(255) NULL,
  is_admin     INT          NOT NULL DEFAULT 0,
  allowed      MEDIUMTEXT   NULL,
  created_at   BIGINT       NOT NULL DEFAULT 0,
  updated_at   BIGINT       NOT NULL DEFAULT 0
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- アプリ内ログイン：ログインセッション
CREATE TABLE IF NOT EXISTS sessions (
  token      VARCHAR(64) NOT NULL PRIMARY KEY,
  username   VARCHAR(64) NULL,
  is_admin   INT         NOT NULL DEFAULT 0,
  created_at BIGINT      NOT NULL DEFAULT 0,
  expires_at BIGINT      NOT NULL DEFAULT 0
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 5. 既存データの移行（引き継ぐ場合）

旧サーバーの内容（項目・在庫）を引き継ぐ場合は、旧サーバーで各テーブルを
エクスポートし、移行先でインポートします。

**旧サーバーで書き出し（例: mysqldump）**
```bash
mysqldump -h 旧DBホスト -u 旧ユーザー -p 旧DB名 nodes inv_items inv_logs app_settings users sessions trips > casebycase.sql
```
（phpMyAdmin の「エクスポート」で `nodes` `inv_items` `inv_logs` `app_settings` を選んでも構いません）

**移行先で読み込み**
```bash
mysql -h 新DBホスト -u 新ユーザー -p 新DB名 < casebycase.sql
```
（phpMyAdmin の「インポート」でも可）

> **画像・添付ファイル**は DB ではなく `uploads/` フォルダにあります。
> 本文に貼った画像を引き継ぐには、**`uploads/` フォルダの中身も一緒にコピー**してください。

## 使い方（画面）

- **案内モード**: 大項目 → 分岐 → 最終作業項目まで選択で進む。
  - 表示中の項目は右上「この項目を編集」で直接修正、下部「＋ ○○を追加」でその場に子項目/大項目を追加できます。
  - 本文の**文字装飾**（編集ダイアログのボタン、または記法で入力）:
    `**太字**` / `[color=red]色付き[/color]`（red,blue,green,yellow,cyan,white,#RRGGBB）/
    `[big]大[/big]` `[xbig]特大[/xbig]` `[small]小[/small]` / 行頭 `# 見出し` `- 箇条書き`。
- **編集モード**: 追加・修正・削除・並び替え（ドラッグ&ドロップ対応）。変更は即サーバーへ共有。
  - 項目のタイトルをクリックすると内容を編集できます。
  - 並べ替えで**別の項目に重ねて「子項目にする」＝階層が変わる移動**のときは、
    誤操作防止のため**確認ポップアップ**が出ます。同じ階層内での並べ替え（親が変わらない）は
    確認なしでそのまま反映されます。
  - 説明欄では **「画像を追加」「ファイルを添付」** ボタン、または **貼り付け（Ctrl+V）** で挿入。
  - **記入者名** を入れておくと、追加・修正した人と時刻が記録されます。
  - **Excel一括登録 / Excel出力 / Excelひな型**: 文章の一括入力・下書きに便利（アウトライン形式。**装飾やユーザー権限は含みません**）。
  - **💾 完全バックアップ / ↻ バックアップ復元**: **色・文字サイズ・入力欄（テキスト/チェック）・ユーザー権限まで、まるごと**保存/復元（下記）。
  - **サーバー連携**: 接続状態、編集トークン、「最新に更新」、「この端末の内容をサーバーへ登録」。

### 完全バックアップ（JSON）— サーバー移行・世代バックアップ向け（管理者のみ）

Excelのアウトライン形式では**装飾（色・文字サイズ）・保存した入力欄・ユーザー権限**は保存されません。これらを含めて**まるごと**残したいときは、修正画面の **「💾 完全バックアップ」** を使います。

- **含まれるもの**：全項目の**本文（色・文字サイズ・テキスト/チェック入力欄をそのまま）**、階層・並び順・登録者名・日時・**閲覧ロック**、**ユーザーとページ権限（パスワードを含む）**、**在庫データ**、**交通費データ**、**ピン留め・ロゴ・各種ON/OFFなどの設定**。
- **出力**：「💾 完全バックアップ」→ `casebycase-backup-YYYY-MM-DD.json` がダウンロードされます。
- **復元**：「↻ バックアップ復元」→ そのJSONを選ぶ → 確認 → **サーバー上の全データを、そのバックアップで置き換え**ます。
- **サーバー移行**：新サーバーにアプリを設置したら、旧環境で出した完全バックアップを「復元」すれば、**装飾も権限もそのまま**移せます（DBの`mysqldump`が使えない/面倒なときの簡単な移行手段にもなります）。

> ⚠️ このJSONには**ログインのパスワード情報（ハッシュ）**が含まれます。ファイルは第三者に渡らないよう安全に保管してください。

### 自動バックアップ（毎日・管理者権限で自動作成）

上記の完全バックアップを、**毎日自動で**サーバーの `backups/` フォルダに保存する仕組みです。手動での「💾 完全バックアップ」操作は不要です。

- **タイミング**：毎日**12時（正午）以降**に、誰か1人でもアプリを開く（＝サーバーへアクセスする）と、その日ぶんの完全バックアップが自動で1件作成されます。同じ日に何度アクセスしても、その日の分は最初の1回しか作成しません（上書きしません）。
- **仕組み**：定時に動く「本物のcron」ではなく、**アクセスをきっかけに作る方式**です（WordPressの `wp-cron` と同様の考え方）。レンタルサーバー側でcronの設定をしなくても動きます。ただし、**その日1日まったく誰もアプリを開かなかった場合は、その日の分は作成されません**。ほぼ毎日使われる業務マニュアルであれば、通常は問題になりません。
- **保存先**：`backups/backup-YYYY-MM-DD.json`（1日1ファイル）。中身は「💾 完全バックアップ」と全く同じ形式です。
- **保護**：`backups/` フォルダは `.htaccess` で**直接アクセスを禁止**しています（URLを直接開いても中身は見えません）。パスワードハッシュを含むため、他のフォルダにコピーしたり、アクセス制限のないサーバーに置いたりしないでください。
- **確認・削除**：修正画面の **「📁 バックアップ履歴」** ボタンから、これまでの自動バックアップの**一覧（日付・作成日時・サイズ）**を確認できます。各行から**ダウンロード**（手動バックアップと同じJSON形式）と**削除**ができます。
- **保存期間・件数の上限は設けていません**。ディスク容量が気になる場合は、履歴画面から古いものを手動で削除してください（自動では削除されません）。

> 自動バックアップも「復元」は修正画面の「↻ バックアップ復元」から行えます（履歴からダウンロード → そのファイルを選んで復元）。
> ⚠️ 「復元」は**全置き換え**です（現在の内容は上書き）。復元前に、現在の状態も一度バックアップしておくと安心です。
> ※項目数が非常に多い場合、サーバーの受信サイズ上限（`post_max_size`）に依存します。通常の運用規模では問題ありません。

## 項目ごとの閲覧ロック（パスワード保護）

特定の項目を、パスワードを知っている人だけに見せられます。

- 項目の作成・編集ダイアログで **「🔒 閲覧パスワードでロックする」** にチェックし、パスワードを設定します。
  - 既定は **ロックなし**（従来どおり全員が閲覧可）。パスワードは任意です。
  - ロックした項目は、その **配下（子・孫）もまとめて保護** されます。
  - 案内モードでは 🔒 と「要パスワード」が表示され、開くときにパスワードを求められます。
- **管理者パスワード** はどの項目でも閲覧できます。忘れた項目の確認に便利です。
  - `config.php` の `ADMIN_PW` に設定した値を使います（このマニュアルには値は記載しません）。
- **パスワードの上書き**: 編集ダイアログでチェックを入れたままパスワードを入れ直すと変更できます。
  - パスワード欄を **空のまま** 保存すると、今のパスワードを維持します。
  - **チェックを外して** 保存するとロック解除になります。
- DB(共有)モードでは、ロック項目の本文は **サーバーからも送信されない** ため安全です
  （正しいパスワードか管理者パスワードで解除したときだけ本文を取得します）。

## Excelで一括登録

担当者がExcelでまとめて入力し、取り込めます（アプリ内でSheetJSを使い、外部通信なし）。

1. 編集モードの **「Excelひな型」** ボタンでひな型（`登録用ひな型.xlsx`）を入手（同梱の `template/登録用ひな型.xlsx` でも可）。
2. 「登録」シートに、**大項目 / 中項目 / 小項目 / 内容（手順・説明）/ 記入者** を1行ずつ入力。
   - 同じ大項目・中項目は各行に繰り返してOK（自動でまとめられます）。
   - 中項目・小項目を空欄にすると、上位の項目に内容が付きます。
   - さらに深い階層は「第4階層」「第5階層」列を足せます（最大6階層）。
   - 内容はセル内改行(Alt+Enter)で段落、行頭「- 」で箇条書き、「# 」で見出し。
3. **「Excel一括登録」** ボタンでファイルを選択し、**置き換え**（全入替）か **追加登録** を選びます。
4. **「Excel出力」** で現在の内容を同じ階層形式の `.xlsx` に書き出せます（バックアップ・再編集用）。

## API（api.php）概要

`api.php?action=...`。`API_TOKEN` 設定時、**書き込み系**はヘッダ `X-Api-Token` が必要（閲覧は不要）。

| action | メソッド | 内容 |
|---|---|---|
| `config` | GET | 接続確認（DB接続の有無・トークン要否） |
| `tree` | GET | 全ノードを取得（ロック項目は本文を伏せ `locked:1` で返す） |
| `node_create` | POST `{parent_id,title,body[,lock_enabled,lock]}` | 追加 |
| `node_update` | POST `{id,title,body[,lock_enabled,lock]}` | 更新（ロック設定の変更・上書き可） |
| `unlock` | POST `{id,password}` | 閲覧ロック解除（正しいパスワードか `ADMIN_PW` で対象サブツリーを返す） |
| `node_delete` | POST `{id}` | 削除（子孫も一括） |
| `node_move` | POST `{id,dir}` | 並び替え（±1） |
| `replace_all` | POST `{nodes:[...]}` | 全置換（Excel取り込み・移行用） |
| `upload` | POST (multipart `file`) | 画像アップロード → URLを返す |
| `inv_list` | GET | 在庫の商品一覧 |
| `inv_history` | POST `{item_id}` | 商品の使用履歴 |
| `inv_item_create` | POST `{name,model,qty,note}` | 商品を追加 |
| `inv_item_update` | POST `{id,name,model,note}` | 商品情報を更新 |
| `inv_item_delete` | POST `{id}` | 商品と履歴を削除 |
| `inv_action` | POST `{id,action,qty,note}` | 持ち出し/返却/使用/調整（在庫増減＋履歴記録） |

## キーワード検索

画面右上（案内・編集・在庫のどのページでも）の **「🔍 検索」** から使えます。

- 入力した単語で、**項目のタイトルと本文**、および**在庫の商品名・型番**を横断検索します。
- 各ヒットには、**その項目がどの階層にあるか**をパンくず（例：`TOP › 大項目 › 中項目`）で表示。
  一致箇所は黄色でハイライトし、本文ヒットは前後の文（スニペット）も表示します。
- ヒットをタップすると、その項目まで**一気に移動**します（在庫商品は在庫管理を開きます）。
- ロックされた項目は本文が検索対象外（サーバーが本文を送らないため）。開くときにパスワードを確認します。

## 在庫管理（商品の持ち出し・返却）

案内モードの大項目一覧の先頭にある **「📦 在庫管理」** から使えます。

- 一覧テーブルで **商品名 / 型番 / 現在個数** を表示。行ごとに操作できます。
  - **− 持ち出し**: 現在個数を減らし、いつ・何個・誰が を履歴に記録。
  - **＋ 返却**: 使わずに戻したぶんを現在個数に足し、履歴に記録。
  - **使用（消費）**: 使い切ったぶんを減らして記録（持ち出しダイアログ内で切替）。
  - **履歴**: その商品の全操作（日時・種別・個数・実施者・残数・メモ）を新しい順に表示。
  - **編集 / 削除**: 商品名・型番・メモの修正、商品ごと削除（履歴も一緒に削除）。
- DB接続時は全端末で共有。未接続時はその端末内のみ（localStorage）に保存されます。

### 管理者による修正（数量・履歴）

数量の直接修正や過去履歴の訂正は **管理者パスワード（`config.php` の `ADMIN_PW` に設定した値）** が必要です。

- 入口は2つ：
  - **編集モードのツールバー「📦 在庫を修正（管理者）」** → 管理者パスワード → 在庫画面が「管理者編集モード」で開きます。
  - 在庫画面上部の **「🔒 管理者編集」** ボタン → 管理者パスワード。
- 管理者編集モードでできること：
  - **数量修正（棚卸し）**：現在個数を正しい値に直接セット（差分が `adjust` として履歴に残ります）。
  - **過去履歴の修正・削除**：各履歴行の「修正／削除」から、個数・実施者・日時・メモを訂正、または行を削除。
    修正・削除すると **在庫数と各行の残数を履歴から自動で再計算** します。
  - **商品の編集・削除**。
- 日常操作（持ち出し・返却・使用・履歴閲覧・商品追加）は、これまでどおり誰でも行えます。
- サーバー側でも管理者パスワードを検証するため、パスワードを知らない端末からは修正できません。

### 在庫用テーブル（自動作成されます）

**手動でSQLを実行する必要はありません。** `nodes` テーブルと同様、初回アクセス時に
`db.php` が自動作成します（MySQL / SQLite / PostgreSQL 共通）。テーブル名は次の2つです。

**`inv_items`（商品マスタ）**

| カラム | 型(MySQL) | 内容 |
|---|---|---|
| `id` | VARCHAR(40) PK | 商品ID |
| `name` | VARCHAR(255) | 商品名 |
| `model` | VARCHAR(255) | 型番 |
| `qty` | INT | 現在個数 |
| `note` | VARCHAR(255) | メモ（保管場所など） |
| `sort_order` | INT | 並び順 |
| `created_at` / `updated_at` | BIGINT | 作成/更新時刻(ミリ秒) |

**`inv_logs`（使用履歴）**

| カラム | 型(MySQL) | 内容 |
|---|---|---|
| `id` | VARCHAR(40) PK | 履歴ID |
| `item_id` | VARCHAR(40) | 対象商品ID（INDEX） |
| `action` | VARCHAR(20) | `out`(持ち出し)/`return`(返却)/`use`(使用)/`init`(初期)/`adjust`(調整) |
| `qty` | INT | 増減した個数（返却・初期は＋、持ち出し・使用は＋値で記録し種別で符号判断） |
| `balance` | INT | その操作後の在庫数 |
| `person` | VARCHAR(120) | 実施者 |
| `note` | VARCHAR(255) | メモ |
| `created_at` | BIGINT | 実施時刻(ミリ秒) |

MySQL側で用意するのは**データベース1個だけ**（既存の `LAA0000000-casebycase` をそのまま
使えます）。上記テーブルはその中に自動で作られます。文字コードは utf8mb4 です。

## 交通費（Transportation expenses）

ログイン後、次のどちらかから開けます。
- **「リテイルオンサイト」など“オンサイト”の中項目を開いた一覧の先頭**に、ほかの項目と違う色（黄系）の **「交通費を入力」** が出ます。
- 画面下フッターの **「交通費」** リンクからも開けます。

### 移動手段（車／電車）
- 画面上部の **ラジオボタンで「車」／「電車」** を選びます。**既定は「車」** です。
- 選んだ方の入力欄だけが表示され、**合計もその手段ぶんだけ**を計算します。
  - **車**：出発地点・目的地・距離・ガソリン代・高速代・駐車場代・その他
  - **電車**：出発駅・到着駅・運賃・その他
- 過去に登録した記録は、すべて **「車」** として扱われます（区分は編集画面で変更できます）。

### 登録（各ユーザー・車のとき）
- 入力項目：**日付・店舗名・出発地点・目的地（最大5つ）・片道距離(km)・ガソリン単価(円/km, 既定18)・高速代・駐車場代・その他(発送費・雑費など)・往復・メモ**。
- **日付は手入力できます**（`2026-08-01` 形式。`2026/8/1` などで入力しても自動で整形されます）。
- **「会社から出発」** ボタンで、出発地点に **東京都台東区台東2-1-1**（`config.php` の `TRAVEL_ORIGIN`）が入ります。
- **ガソリン代 = 片道km ×（往復なら2）× 単価**、**合計 = ガソリン代＋高速代＋駐車場代＋その他**（入力に応じて自動計算・金額はサーバー側で確定）。
- **その他** 欄は、発送費・雑費など、走行以外にかかった費用の入力に使えます。
- 登録者名は**ログイン中のアカウント**で自動記録されます。

### 登録（電車のとき）
- 入力項目：**日付・店舗名・出発駅・到着駅（最大5つ）・運賃（複数可）・その他・メモ**。
- **「＋ 到着駅を追加」** で、乗り継ぎの駅を最大5つまで並べられます（車の「目的地を追加」と同じ操作です）。
- **合計 = 運賃＋その他**（距離・ガソリン代・高速代・駐車場代は使いません）。
- **「運賃（複数可）」の隣の「往復」チェック**：片道運賃を入力してからチェックすると、**運賃が自動で2倍**になります。外すと片道の金額に戻ります。
- 運賃の1行目のメモ欄には、**入力した出発駅・到着駅から経路（例：秋葉原→新橋）が自動で入ります**（往復チェック時は「往復」も付記）。メモを手で書き換えると、以後はその内容を保持し、自動更新されなくなります。

### 距離・運賃の確認（別タブで開きます）
- **車：「GoogleMapで距離測定」** ボタンで、**出発地点 → 目的地1 → 目的地2 → …** の経路をGoogleマップの経路案内で**別タブに表示**します。
  そこに出る走行距離を見て、**「片道(km)」に入力**してください（APIキーは不要です）。
- **電車：「Yahoo!路線で運賃を調べる」** ボタンで、**出発駅 → 到着駅**（途中の駅は経由駅として最大3つ）の検索結果を
  **Yahoo!路線情報の別タブに表示**します。そこに出る運賃を見て、**「運賃」に入力**してください（APIキーは不要です）。

### 履歴検索（ポップアップ）・Excel出力
- 交通費の入力画面の上部 **「📋 交通費履歴検索」** ボタンで、履歴検索を**ポップアップ**で開きます（入力画面はそのまま後ろに残ります）。
- **開いた時点では一覧を読み込みません**。月（と対象者）を選んで **「検索」** を押したときに初めて読み込むため、件数が多くても開くのが遅くなりません。
- 一覧の **「編集」** を押すと、その記録が**手前のポップアップ**に表示されます（後ろの入力画面は変わりません）。更新すると一覧が更新されます。
- **月**（または期間）で絞り込み。**管理者はユーザーでも絞り込み**でき、全ユーザーの記録を横断表示します（一般ユーザーは自分の分のみ）。
  - ユーザーの絞り込みプルダウンには、**「リテイルオンサイト」を閲覧できるアカウント**（許可された一般ユーザー＋管理者）が表示されます。
- **移動手段**（すべて／車／電車）でも絞り込めます。一覧には **「区分」** 列が付き、車・電車がひと目で分かります。
- 一覧の一番下に**合計行**（総距離・ガソリン代・運賃・高速代・駐車場代・その他・合計金額と件数）を表示します。
- **「Excel出力」**で、表示中の一覧を `.xlsx`（日付・登録者・区分・店舗名・出発地点/出発駅・目的地/到着駅・距離・ガソリン代・運賃・高速・駐車・その他・合計・メモ）で書き出します。最終行には同じ合計が入ります。
- 各行から**編集・削除**が可能（他人の記録は管理者のみ）。
- ※入力画面では、登録しても一覧は表示されません（履歴は上記の履歴検索で確認します）。

### 交通費テーブル（自動作成されます）

`trips` テーブルが初回アクセス時に自動作成されます（手動SQL不要）。主なカラム：
`id, username, display_name, trip_date, case_name, mode, origin, destination, one_way_km, round_trip, gas_rate, gas_cost, fare_cost, toll_cost, parking_cost, other_cost, total, cost_details, note, created_at, updated_at`
（目的地・到着駅が複数のときは `destination` に改行区切りで保存。`mode` は `car`／`train`、電車の出発駅は `origin`、運賃は `fare_cost` に入ります）。
既存のテーブルには `mode` / `fare_cost` 列が**自動で追加**されます（既存データはすべて `car` 扱い）。
電車の記録では、`round_trip` 列は「運賃を往復で入力したか」のフラグとして使われます（距離の往復とは別の意味です）。

## ヘッダーロゴ

タイトル「CASE BY CASE」の左に、小さくロゴ画像を表示できます。

- **既定でON**で、同梱の `logo-default.png`（背景を透過処理したWELSYSロゴ）が表示されます。
- 右上「修正」画面の **「🏢 ヘッダーにロゴ画像を表示する」** トグルで、**表示ON/OFF**を切り替えられます（**管理者のみ・全端末共有**）。
- 同じ場所の **「📷 ロゴ画像を選ぶ（入れ替え）」** ボタンから、**画像を選ぶだけで自動的にアップロード・切り替え**されます（**管理者のみ・全端末共有**）。png/jpg/gif/webp に対応。切り替えると同時に表示もONになります。
- 入れ替えた画像は `uploads/` に保存され、設定（表示ON/OFF・画像URL）は他の設定と同じく `app_settings` テーブルに保存されます。**完全バックアップ**にもこの設定が含まれます。
- ロゴ画像は横幅に応じて自動で縮小表示されます（高さ約28〜40px）。背景が透過なアイコン画像を使うと、ヘッダーになじみます。

## アップデート（差し替え）時の注意

データ本体は **MySQL（DB）に保存**されます。アプリのファイル（`manual.*` / `api.php` /
`db.php` / `vendor/` など）を新しくしても **DBの中身は消えません**。ただし次のものは
**上書き・削除しないでください**。

| 対象 | 理由 |
|---|---|
| `config.php` | DB接続情報（サーバー名・パスワード）。**上書きするとDBに繋がらなくなり、各端末が「この端末のみ」表示になって内容が食い違います。**（更新用ZIPには同梱していません） |
| `uploads/` の中身 | アップロードした画像・ファイルの実体。消すと添付が表示できなくなります |
| `data/` の中身 | SQLite利用時のDB本体。MySQL利用なら無関係ですが、消さないのが無難 |
| `backups/` の中身 | 毎日自動作成される完全バックアップ。消すと過去の自動バックアップ履歴が失われます |

更新手順:
1. 更新用ZIP（`config.php` を含まない）をFTPでアップロードして上書き。
2. 各端末で**ブラウザを再読み込み**（スマホでPWA追加済みならアプリを再起動）。

## 「スマホとPCで内容が違う」ときの確認

内容が共有されるのは、画面上部のチップが **「● 共有中」** のときだけです。

- **● 共有中** … DBに接続済み。全端末で同じ内容が見えます。
- **● DB未接続** … `config.php` の設定（パスワード等）またはPHPバージョンを確認。
- **● この端末のみ** … サーバーに繋がっておらず、その端末の編集は共有されません。

食い違う場合のチェック:
1. 各端末で上部チップが「● 共有中」か確認（違えば config.php を確認）。
2. 編集トークンを設定している場合は、各端末で同じ合言葉を入力。
3. それでも古い場合は編集モードの「最新に更新」ボタン、またはブラウザ再読み込み。

## セキュリティ / 運用の注意

- **公開URLで運用する場合は `API_TOKEN` を必ず設定**してください（未設定だと誰でも編集可能）。
- `config.php`（DBパスワード等）は Git に含めません。サーバーへ直接アップロードします。
- `uploads/` は同梱の `.htaccess` でPHP等の実行を禁止しています（画像のみ配信）。
- 定期バックアップは「Excel出力」または ロリポップのDBバックアップ機能をご利用ください。

## SQLite で試す（任意）

MySQLを使わず手軽に試すには、`config.php` で `DB_DRIVER='sqlite'` にすると
`data/manual.sqlite` に保存されます（少人数・簡易用途向け）。本番は MySQL を推奨します。

## 将来のスケール

`db.php` の DSN を差し替えるだけで PostgreSQL 等にも対応可能（PDO）。
画面側（`manual.js`）は変更不要です。
