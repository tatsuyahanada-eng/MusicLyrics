# ライブラリポータル

関連会社で共有する資料・プログラム・アプリの**更新履歴**を管理する Web アプリケーションです。

- 構成：PHP 8 + MySQL 8（さくらのレンタルサーバを想定）
- 形態：PWA（ホーム画面に追加してアプリとして利用可能。HTTPS 必須）
- 権限：**管理者**（フルコントロール）／**閲覧のみ**（一般利用者）

## 画面

表示は **本棚** と **一覧** を切り替えられます（選んだ方は次回も引き継がれます）。

### 本棚ビュー（既定）

CD ラックのように、資料を**横に寝かせて積んだ**棚です。
背が横向きなので名称は横書きのまま読め、棚を眺めるだけで更新の歴史が分かるよう、
1 枚 1 枚の見た目そのものに意味を持たせています。

| 見た目の要素 | 意味 |
|---|---|
| **厚み** | 更新回数。よく手が入っている資料ほど厚い |
| **目盛り** | 更新 1 件ぶん。区分の色（機能追加＝緑／不具合修正＝赤／改善＝白／資料改訂＝金／初版＝淡緑）で塗る |
| **装丁の色** | 種別（アプリ＝青／プログラム＝黒／資料＝茶／マニュアル＝小豆）。見分けやすさを優先し、彩度を落とした4色を使い分ける |
| **左端の縞** | 紙の束（小口）。横積みであることを示す |

1 枚を選ぶと、それがラックから右へせり出し、**そのすぐ下で中央の綴じ目を軸に左右のページが開きます**。

| ページ | 内容 |
|---|---|
| **左ページ** | 名称・作成者・**最新Ver**・説明・URL・奥付（公開開始／更新回数／直したファイルの延べ件数と種類数／最終対応者）・**版数の道のり** |
| **右ページ** | **更新の年表**。年ごとにまとめ、**新しい順**に並べます。一覧には「日付・版数・更新内容」だけを出し、<br>行を押すとその 1 件の詳細（版数の遷移・区分・対象機能・対応者・管理番号・**実際に直したプログラム・ファイル**・**添付ファイル**）が開きます。<br>見出しの **「全ての更新履歴」** を押すと、すべての詳細をまとめて開けます |

### 添付ファイル（画像・PDF・ZIP）

更新を登録・修正するときに、配布するファイルそのものをアップロードできます。
更新1件につき1つ、履歴の各回に結びつくので、**過去のバージョンのファイルもあとから取り出せます**
（＝ファイルの世代管理）。URL（外部の共有場所）を設定していないアイテムでは、
一覧・見開きの「開く」が自動的に最新の添付ファイルのダウンロードに切り替わります。

- 許可する種類：画像（jpg / png / gif / webp）・PDF・ZIP。中身も確認するので拡張子の偽装は弾きます
- 上限サイズ：既定 20MB（`includes/config.php` の `upload_max_bytes` で変更可）
- ダウンロードはログイン済みの利用者のみ。ファイルの実体は `uploads/` に置き、
  ブラウザから直接は開けないようにしてあります

### 版数（バージョン）の決まり

版数はデータベースに持たず、**更新の登録順から自動で決まります**。
更新を登録するときに選ぶ「更新の大きさ」だけが記録され（`lp_updates.bump_type`）、
表示のたびに計算されるため、あとから履歴を直せば版数も自動で振り直されます。

| きっかけ | 版数 |
|---|---|
| 最初の登録（＝出発点） | `1.00` |
| 通常の更新（`minor`） | `1.1` → `1.2` → `1.3` … |
| 微修正（`revision`） | `1.1` → `1.11` → `1.12` … |

繰り上がりの決まり（自動）：

- 微修正が 9 を超えたら、次の通常の更新へ繰り上がります（`1.19` の次は `1.2`）
- 通常の更新が 9 を超えたら、メジャーが繰り上がります（`1.9` の次は `2.00`）

計算は `includes/helpers.php` の `lp_version_series()` が唯一の決まりで、
画面側（`assets/library.js` の `numberVersions()`）は見本ページ用の同じ写しです。

同じファイルを複数回直している場合は、ファイル名の横に **「2 回目」** のように回数が付きます。
どこを繰り返し触っているかが履歴から追えます。

### 一覧ビュー

従来どおりの表形式です。件数が多いときの検索・確認向け。
行をクリックすると、その資料の更新履歴が下に開きます。

## 配色

ボストン・セルティックスの配色（グリーン・ディープグリーン・ホワイト・ブラック）を基調とし、
ゴールドをハイライトに使用しています。値は `assets/library.css` の `:root` に集約しているため、
色を変える場合はこのブロックだけを編集してください。

| 用途 | 変数 | 値 |
|---|---|---|
| 主要アクション・リンク | `--lp-green` | `#007a33` |
| ホバー・強調 | `--lp-green-bright` | `#0f9b48` |
| ヘッダー・見出しの強調 | `--lp-deep` | `#00401d` |
| ハイライト（展開中の行・最新の更新・主要ボタン） | `--lp-gold` | `#ba9653` |
| 本文・管理者バッジ | `--lp-ink` | `#0e1311` |
| 面 | `--lp-white` / `--lp-bg` | `#ffffff` / `#f5f8f6` |

注意・エラー（必須項目、不具合修正の区分、削除ボタン、停止中の表示）だけは、
判別のため落ち着いた赤 `--lp-danger`（`#9e2a2b`）を最小限で使用しています。

## アイコン（PWA）

`assets/app-icon-source.png` を正本として、以下を生成しています（生成スクリプトの内容は
`docs/deploy-sakura.md` の更新手順を参照。元画像を差し替えた場合は同じ手順で再生成してください）。

| ファイル | 用途 |
|---|---|
| `assets/icon-192.png` / `icon-512.png` | ホーム画面・アプリ一覧のアイコン（`manifest.webmanifest`） |
| `assets/icon-maskable-512.png` | Android の adaptive icon（安全領域に収まるよう中央配置） |
| `assets/favicon-32.png` / `favicon-16.png` | ブラウザタブのファビコン |
| `assets/app-icon.png` | 画面内（ヘッダー・ログイン画面など）に表示する等身大のアイコン |

ヘッダーおよびログイン／初回セットアップ／オフライン画面では、このアプリアイコンと
WELSYS ロゴを並べて表示しています。アイコン画像を更新した際は、ファイル名は変えずに
中身を差し替えたうえで、`?v=` のクエリ番号（HTML・`manifest.webmanifest`・
`service-worker.js` の該当箇所）を 1 つ上げてください。番号を上げないと、インストール済みの
端末では Service Worker と画像キャッシュにより古いアイコンが表示され続けます。

## 設置手順

`docs/deploy-sakura.md` を参照してください。要点は次の 5 つです。

1. さくらのコントロールパネルで MySQL データベースを作成
2. phpMyAdmin で `sql/schema.sql` → `sql/seed_admin.sql` の順にインポート
   （すでに動いているものを新しくする場合は、代わりに `sql/upgrade.sql` を実行してください。
   何度実行しても安全で、足りない列だけを追加します）
   （ログインID `welsys` / パスワード `Password` の初期管理者が作成されます）
3. このフォルダの中身を公開ディレクトリへ転送（`preview.html` は不要）
4. `includes/config.sample.php` を `includes/config.php` にコピーして接続情報を記入
5. `welsys` / `Password` でログイン → **すぐにパスワードを変更** → `setup.php` を削除

`seed_admin.sql` を使わず自分で最初の管理者を決めたい場合は、代わりに
`setup.php` を実行してください（`docs/deploy-sakura.md` の手順5に両方を記載）。

## 権限

| | 閲覧・ダウンロード | アイテム登録 | 更新履歴登録 | 利用者管理 |
|---|:--:|:--:|:--:|:--:|
| 管理者 | ○ | ○ | ○ | ○ |
| 閲覧のみ | ○ | × | × | × |

権限は設定画面の行内スイッチでいつでも切り替えられます。
画面表示だけでなく API 側でも検証しており、URL の直接入力では操作できません。

## 共通ユーザーデータベース（複数アプリ共通・SSO）

`includes/config.php` の `auth_mode` を `'central'` にすると、利用者情報を
共通ユーザーデータベース（`auth_users` / `auth_app_roles`）から取得します。

```php
'auth_mode'    => 'central',
'app_key'      => 'library',   // 共通DB上でのこのアプリの識別子
'default_role' => 'none',      // 権限行が無い利用者はログイン拒否
```

権限は共通DBに **アプリ単位の行**（`app_key` + `user_id` + `role`）として保存されるため、
「ライブラリでは管理者、別アプリでは閲覧のみ」を表現でき、他アプリへ権限が漏れません。
設計・検証結果・移行手順は `docs/sso-central-users.md` を参照してください。

| | `local`（既定） | `central` |
|---|:--:|:--:|
| このアプリでの権限変更 | ○ | ○ |
| アカウント作成・削除・停止・パスワード | ○ | 共通の利用者管理へ集約 |

## セキュリティ

- パスワードは `password_hash()`（bcrypt）で保存。5 回連続失敗で 10 分ロック
- 書き込み API は CSRF トークンを検証
- SQL はすべてプリペアドステートメント
- 出力は HTML エスケープ済み。ダウンロード URL は `http(s)` のみ許可
- `includes/` `sql/` `docs/` `uploads/` は `.htaccess` で直接アクセスを禁止
- 添付ファイルは拡張子・中身（MIME）の両方を確認してから保存し、`download.php` はログイン確認後にのみ配信
- ログイン・登録・利用者変更は `lp_audit_log` に記録
